## 正文落在哪张台子上（六关的承载点）

正文不进附录，也不在交互台后面另起一纸。真源里的每一节，都要对着一张具体的东西落下：

| 关 | 台子 | 正文的落点 |
|---|---|---|
| ① | 五张会翻面的实物卡 | 卡片正反面就是正文；页尾只留一张链接表 |
| ② | 趋势分拣台 | 情报卡、两个档案格、页首数据展台（共享数字只在这里出现一次） |
| ③ | 实验室 | 引导正文与三件作品条目挂在同一节；`algorithm-lab` 内嵌程序保留 |
| ④ | 副业路线台 | 选中哪条路线，详情面板里就摊开真源那一层的卡片（正文 / 步骤 / 工具 / 注意） |
| ⑤ | 八幕决策室 + 撕纸账页 + 话术滚筒 | 心理机制 / 两条真数字 / 工具挂在「解剖这一幕」后的参照抽屉；撕纸账页默认展开，留核验结论；滚筒的六种说法来自话术词典 |
| ⑥ | 提示词学院 | 三课分别长在校准台、试投、样例站与检查站里，不再另排一节 |

写新文案时先想清楚这句话**落在哪个可点的东西上**；落不下去，说明它属于别处，别硬塞。

## 一、读者画像与语言原则

- **第一读者**：55—65 岁的中国妈妈（含退休财务、保险从业者等职业背景设定）。她有丰富的生活与职业经验，但对"AI"这个词可能只停留在新闻印象。
- **口语化**：像当面聊天，不像写教材。短句为主，一句只说一件事。多用"你"，少用"我们""用户"。
- **不吹不吓**：不渲染"AI 万能"，也不渲染"AI 抢饭碗"。每一段落最终落到"这对你的启示"。
- **术语首次出现必须给中文解释**（括号夹注或一句话解释），同一页内只需解释一次：
  - 生成式 AI（能自己"写"出文字、图片、视频的人工智能）
  - 大模型（支撑 AI 产品的大型"大脑"程序）
  - 提示词（Prompt，你发给 AI 的那句话——指令）
  - 开源（代码公开，人人可以免费拿去用）
  - 智能体（Agent，能领了目标自己干完整件事的 AI）
  - 文生视频（一句话让 AI 生成视频）
- **emoji 只作视觉路标**（🛒📱💼📊🎓 等），不堆砌，不替代文字。
- **示例人名、场景**（王姐、跳舞班、社区活动室）用日常可信的生活场景，不用夸张剧情。

## 二、"演示内容必须标注"原则（硬规则）

1. 页面上所有**由我们写出来的 AI 回复样例**（对话气泡、生成文案），必须能让读者一眼分辨"这是演示"。手段：
   - 卡片角落的显式徽标，如 `🎭 演示对话 · 数字为示意`；
   - 页面级"诚实声明"卡集中说明；
   - 时间对比类数字（"约 3 小时 → 3 分钟"）后缀 `（示意）`。
2. **真实的东西必须点名真在哪里**：本站代码本身、每条可照抄的提示词、截图、开源项目链接。
3. 每个演示样例必须附**验证方式**：给出官方工具的真实网址，让读者可以亲手复现。P1 的演示验证渠道：
   - 豆包 <https://www.doubao.com>（对话、修照片演示的验证渠道）
   - 即梦 <https://jimeng.jianying.com>（AI 画图类演示的验证渠道）
   - 剪映 <https://www.capcut.cn>（图文成片等视频演示的验证渠道）
4. 手绘示意图（SVG 画的"照片修复对比"等）**不得伪装成实拍**：图注必须写"示意图"，画面内容在 `aria-label` 里如实描述。

## 三、数据与事实规则（硬规则）

1. **所有数字必须有官方权威来源**，正文用 `[来源N]` 标注，对应 `sources-p123.md` 清单。
2. **首选官方文件**：如 CNNIC《生成式人工智能应用发展报告（2025）》优先引用 CNNIC 官网发布页（cnnic.net.cn），再用新华网、人民日报海外版等权威媒体报道交叉印证。
3. **行业功能举例**（淘宝 AI 商品图、剪映"图文成片"）必须给官方产品页或权威媒体报道链接，不用自媒体二手转述。
4. **拿不准的数字一律删掉或改定性表述**（"越来越多""不少""几分钟"），禁止编造、禁止凭记忆填数。
5. 定性描述的行业趋势（如"银行智能客服背后越来越多是 AI"）在来源清单里注明"定性表述，依据 XX 报告应用章节"。

## 四、引用格式

- 正文内：`[来源N]`，N 为 `sources-p123.md` 里的全局连续编号。
- 页面"来源"区块与本文档文末：链接清单**每条必须含**——名称、发布方、URL、验证状态码、访问日期。
- 访问日期统一记 `2026-11-05`；日后更新文案需重新验证并更新日期。
- 引用格式示例：
  > 我国生成式人工智能用户规模达 5.15 亿人，普及率 36.5% [来源4][来源5]

## 五、链接可用性规则（硬规则）

1. **每个对外链接上线前逐一验证**，方法：
   ```bash
   curl -sI -o /dev/null -w "%{http_code}" "<url>"
   # 需要跟随跳转时：
   curl -sIL -o /dev/null -w "%{http_code}" "<url>"
   ```
2. 记录状态码：200 为通过；302 跳转后最终 200 也算通过（记 `302→200`）。
3. **被反爬挡住的链接**（403/418）：如是官方域名且已知浏览器可正常访问，可保留，但必须注明"官方域名，浏览器可访问，curl 返回 403"，并尽量补一条可验证的权威媒体链接交叉印证。
4. **打不开的链接（404/超时/死链）直接换替代来源或整条剔除，绝不留死链**。被剔除的记录在 `sources-p123.md` 末尾。
5. 站内相对链接（如 `academy.html`、`assets/embed/...`）随仓库走，不在此清单，但改路径时需同步本文档。

## 六、文案到页面的对应方式

- 本目录文档按**页面区块**组织（`##` 二级标题 = 页面区块，`###` = 卡片/条目），条目内列出该卡片的全部文字（正/背面、按钮、图注、脚注）。
- 文档只管"说什么"，不管排版（颜色、栅格、动画不在此记录）。
- 演示样例的验证方式以"验证方式"小字条目附在对应演示之后。

## 七、构建与自检

```bash
# 在仓库根目录执行；产物是 ai-exploration-base/prototype/*.html
python3 ai-exploration-base/scripts/build-source-pages.py
```

- **幂等**：连跑两次，`prototype/*.html` 的 md5 必须一致；不一致说明脚本里有随机或漏改的拼接。
- **两个宽度**：1280 与 375 各看一遍——无横向溢出、无控制台报错、该点的还能点。
- **版本戳**：改了 `prototype/*.js` / `*.css` 就递增页面里的 `?v=`，否则读者拿到的还是旧缓存（对照根目录 `README.md` 的版本表）。
- **生成物别手改**：`prototype/chapter-0X.html`、`prototype/route-fill.js` 都由脚本产出。
