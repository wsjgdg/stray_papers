## 二、穹顶追捕（Planned · 先不做）

**设定的理据**：玩家的船被穹顶算进了 `STARFALL` 的统计里，也就是一个"未申报的坠落物"。镜务院在理论上必须来清点它。

**为什么现在不做**：一旦有追捕，就必须有失败状态、重置、存档与惩罚设计——那是另一套系统，会改变这个项目"观景器"的性质。先想清楚要不要，再动。

**草案（等确认后再细化）**

- **触发**：玩家在同一片区域停留超过 X 分钟，且期间见证过 ≥1 次作业（等于暴露在读数里）。
- **表现**：不是敌人，而是**光**——一束从天空斜打下来的搜索光柱，缓慢扫过地表；被扫到时 HUD 出现一行很小的字（`UNFILED OBJECT`）。
- **应对**：走进圣所的光柱里（灵脉噪声掩护）、或在 `BLOOM TIDE` 期间移动（世界到处在发光）。
- **失败**：被扫到 3 次 → 不是死亡，而是**"被记录"**：地图上永久多一个标记，之后每次作业都会多一次扫描。
- **代价**：会让"观景"变成"逃跑"。**可能最后决定永远不做。**

## 三、沉默者苏醒（Planned · 先不做）

**设定的理据**：走音者的每一次"错音"都在给沟底发信号（`WORLD.md` §6.5）。

**草案**

- **计量**：全局累计 `detune.count`（已在 `diagnostics()` 里暴露）。
- **第一阶段（≥ 20 次）**：夜里海面出现缓慢移动的暗色块（回声群上浮），没有交互。
- **第二阶段（≥ 50 次）**：无光沟方向出现规律的低频脉冲（音效），潮汐钟失常（圣所光环节拍错乱）。
- **第三阶段（≥ 100 次）**：`SOLAR VEIL` 期间，沟底升起"溺者之影"——这是整个星球唯一的敌对存在，也是主线入口。

**注意**：这三个阶段都要求"跨会话累计"，所以需要存储（`localStorage`）。如果决定不持久化，就只能做成单次会话内的演出。

## 四、待排期的低成本项

1. ✅ **大陆命名**：`provinceAt()` 用纬度 + biome 推断五块大陆之一，读数条第一段显示（`VAELMAR` / `SENNAR` / `CAELTH` / `MIRELLA` / `VESSPER`）。
2. ✅ **水域三分**：`waterAt()` 按深度分 `MIRROR SEA`（< 50 m）/ `CIRCLING OCEAN`（50–170 m）/ `VANE TRENCH`（> 170 m），读数条第二段显示水深。
3. ✅ **档案面板**（`O` 键）：五项作业的「官方口径 / 真相 / 破绽」+ 五大陆（政体/建筑/生物/正史）+ 三水域 + 三条「故意不归档」。半透明侧栏、不暂停世界、`Esc` 关闭；打开时释放指针锁定并清空输入。

> 教训（写给未来的自己）：
> 1. `nearDirection(base, angle, d)` 的 `d` 是**弧度**（1 rad ≈ 4.2 世界单位），而建筑尺寸是**世界单位**。第一次做聚落时就栽在这里——`0.14` 看着像 14 cm，其实是 0.6 个单位，正好把聚落埋进圣所岛基。
> 2. 视点相关的所有高度必须同源：脚底曾经被 `Math.max(elevation, SEA)` 夹住，而水里又换了一套眼高，于是入水瞬间正好跳「水深 + 站高差」。现在的规则是**一条连续曲线**，改数值前先确认两条曲线仍然相交。
> 3. 跟随相机的粒子必须活在世界空间：每帧用相机位置重建位置，看着"在动"，其实零视差，任何一次转头都会被读成卡顿。
> 4. **alpha 混合不能吸色**：想让水"吃掉红光"，靠调 alpha 是做不到的——`src*a + dst*(1-a)` 里没有给背景乘透过率的项。所以吸收必须体现在**水自身颜色 + alpha 的组合**上（按 Snell 光程算 alpha，把水色按深度预先拌好），否则浅水看起来就是"没上色的沙子"。
> 5. **屏幕空间折射 = 再渲一遍场景**：想用帧缓冲做像素位移，就得每帧多一次全场景渲染（或额外深度 RT + 手写深度测试），在这颗星球上等于 GPU 翻倍，换来的只是浅水位移几个像素。宁可把预算给"透射 + 光程吸收 + 折射焦散"。这条如果哪天要推翻，先量帧时间。
> 6. **植被要按气候"能长不能长"来分，不是按噪声阈值**：把物种挂在地貌（desert/tropical…）上，等于让植物跟着噪声长，最后每块陆地都是"什么都有、什么都不明显"。改成 **省 → 物种清单 → 省内海拔/湿度分工** 之后，Vessper 可以真的一棵不长，而 Vaelmar 能同时有针叶、橡树和垂柳。清单里没有的物种连候选点都不会生成。
7. **候选取点用"每省一个池子"而不是全局拒绝采样**：全局撒点再按省过滤，只有约 `8%` 的采样能命中某个省，配额一大就跑不满（实测棕榈只能落 `113/300`）。改成先按省把陆地采样点分桶（`36000` 个 Fibonacci 点一次分完，约 `45 ms`），每个物种从自己省的池子里按洗牌顺序取、跨物种不复用同一点 —— 配额全满、不会有两株长在同一点。
8. **行省这种"地图读色"必须天生连续**：按地貌（沙漠/苔原/高山）就地判定，等于让色块跟着噪声走——同一块大陆会被撕成碎屑。改成**加权最近种子划分**后，边界是一条连续曲线，权重还能直接配平面积。判据是可测的：相邻陆地点同省率 `99.7%`、每省陆地占比极差 `5.5` 个百分点。
7. **传送锚点从已有聚落里挑，不要自己撒点**：聚落生成时已经保证了 `heightAt ∈ [0.03, 0.26]`（陆地、非断崖、非浅滩），直接拿来当锚点，天然满足"不在海里"；再用洗牌 + 最小间隔贪心，既均匀又不偏向任何省。
8. **canvas 小地图别每帧重采样球面**：`heightAt` 一次要两层噪声，圆盘全量 `320` 格就是 `0.4 ms` 起。改成"每帧只扫一环"后成本摊平到 `0.5 ms`/帧（含 15 Hz 重绘）；而且位置直接投到玩家切向基上，"跟着头转"是免费的，不需要维护任何角度变量。
> 7. **地图的格子千万不要相对镜头存**：镜头一转/一走，同一格被重新采样到不同的世界位置，"扫一半"和"扫一半"永远不一致——用户看到的就是海岸线一秒是水一秒是地。**世界锚定 + 旋转位图**才是对的顺序：位置进缓存，朝向上屏。
> 9. **地图这种"读数"不要有任何运行时重算**：三轮下来结论很硬——运行时每多做一件事（每帧扫环、按需重烘、预算切片），就多一处卡顿和一处时序不一致。能在加载期算完的，就不要留到运行时；运行时就该只有一次 `drawImage`。
> 10. **等距圆柱图 → 切平面是仿射**：`rotate` 管朝向、`scale(1/cos(lat), 1)` 管经度拉伸，一张 `drawImage` 就能得到"脚下这一圈"，不需要逐像素投影。前提是**网格的 u/v 约定要和图一致**——`THREE.SphereGeometry` 的 `u = atan2(z,-x)/TAU + .5`（`u` 与经度的关系是 `lon = u·360° − 90°`），搞错这半步整张地图会整体转 90°。
> 8. **`strokeStyle`/`lineWidth` 在大量 `fillRect` 之后可能不可靠**：沙盒的 canvas 实现里，3136 次 `fillRect` 之后紧跟的 `stroke()` 只剩 1 px（同级隔离测试正常）。烘焙线稿改用 `fillRect` 画 1~2 px 的实心线段，既不依赖线条状态，也更快。

### v4：水、顶栏、巡检图（2026-11-01）

1. ✅ **水面透射**：`waterMaterial` 改 `transparent: true` + `depthWrite: false` + `ocean.renderOrder = 8`；片元不再画 `sandFloor`，改成按 `cosT = sqrt(1 − .5625 (1 − cosI²))`、`pathLength = depth / cosT`、`alpha = 1 − e^(−46 · pathLength)` 的透射；菲涅尔/泡沫/焦散/雾各自夹一次 alpha。深度曲线：`5 m .05 / 8 m .21 / 19 m .60 / 34 m .84 / 65 m .98`。
2. ✅ **`O` 图标**：从右下角漂浮胶囊搬进 `.top-actions`，改成 `14 px` 图标 + `8 px` 的 `O` 字样，与天气/声音按钮同级；旧定位与手机专用定位规则一并删掉。
3. ✅ **巡检图**：`#minimapFrame` + `256²` canvas；五层（水陆线 / 省界 / 聚落 / 圣所+灵脉 / 兽群）；只在 `data-mode="ground"` 且非过场时显示。
4. 🔧 **巡检图返工（第一轮）**（用户："上一秒是水，下一秒又不是了 / 不动也要几秒"）：原因是**格子是相对镜头的**——每帧扫一环，10 帧扫完一圈，扫的上下半圈永远对不上，海岸线就来回跳；而且每帧 `32 heightAt + 32 provinceAt`、`15 Hz` 全量重排 canvas、圆盘上还挂着 `backdrop-filter: blur()`。改成**世界锚定的补丁位图**：`±0.58` 单位 / `56×56` 格 / 只烘内切圆 `2472` 格（`baseMeshRadius`，不走噪声），海岸线与省界一起烘进去，之后每帧只做一次旋转 `drawImage`。站着不动逐像素一致、转头 0 采样、走路每 `0.085` 单位才重烘一次（`1.1 ms/帧` 预算切片 + 双缓冲），稳态 `0.01 ms/帧`。
5. 🔧 **巡检图返工（第二轮，用户："还是不行，能不能提前做好整个地图"）**：用户是对的——"按需重烘"这条路线在地图上永远是错的，只要还有"烘"这个动作，就有卡顿和时序。现在改成**加载期把整颗星球画完**：`2048×1024` 等距圆柱图（窄屏减半），陆地/海洋取地形网格顶点的半径（网格天生就是等距圆柱排布，一次 `hypot`，不碰 `heightAt`），省界逐像素 `provinceAt`，海岸线与省界画进同一张图；运行时**零采样**，只有一次带旋转 + `1/cos(lat)` 拉伸的 `drawImage`，并且**每 3 帧才重绘一次**（20 Hz 间隔采样）。烘一次约 `250 ms`（Node 实测），藏在加载画面后。
