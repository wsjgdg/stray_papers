# 会议纪要工作台

个人单机版的会议档案工具：粘贴录音转写稿，自动生成一句话摘要、分议题纪要、带原文引用的行动项与决议；支持跨会议问答、语义搜索、跟进中心与知识图谱。**所有数据只存在浏览器本地**（localStorage + IndexedDB），可一键导出备份，敏感场景可选开启静态加密（档案加密，见第七节）。

技术栈：React 19 + TypeScript + Vite + Tailwind CSS 3 + shadcn/ui（Radix）+ cmdk。全部依赖锁定为精确版本（依赖治理见第十节）。

### 右栏内容策略（RightPanel）

- **阅读摘要时**：本场日期 / 系列 / 标签、未完成行动项与决议计数、低置信「待核对」数、可能相关的会议（共同标签 / 文本相似 / 共同负责人加权，理由可读，见 `useMeetingNotes.ts` 的 `relatedMeetings`）、最近动态（`loadActivity`，localStorage 事件日志）
- **核对原文时**（转写页签）：说话人列表（`parseTranscriptLines` 实时统计发言行数）、议题锚点、清洗统计（`cleanReport`）
- **行动项 / 决议 / 跟进页签**：按人分布（完成率 + 逾期占比进度条，数据来自 `workload`）、按时间汇总（`dueCounts`）
- **全局视图页签**（时间线 / 图谱 / 问答）：这些页签跨全部会议，右栏不再显示单场会议上下文，改为**档案概览**（会议总数 / 标签 / 未完成行动项 / 负责人数）+ 按人分布 + 最近动态，并提示「回到某场会议的页签可查看它的上下文」
- **未选中会议**：档案概览 + 最近动态

### 双模式（阅读 / 对照）

- **阅读模式（快捷键 `R`）**：纪要页签为主——一句话摘要 → 分议题要点 → 行动项与决议内联区 → 折叠的转写全文，一屏完成「先看结论」
- **对照模式（快捷键 `C`）**：转写（左）与摘要（右）并排渲染；点击行动项 / 决议里的出处引用（`SourceAnchor`，字符级偏移），左侧转写在 textarea 中精确选中对应片段（`TranscriptTab` 的 `locateTarget` 机制）
- 实现：`Workbench.tsx` 的 `CenterHost` 按 `compareActive` 分支，复用 `TranscriptHost` + `SummaryHost` 左右并排；页签行右侧有分段切换器（含 R / C 快捷键提示）

## 二、命令面板（⌘K / Ctrl+K）

「我想找某个东西」的统一入口，替代「记哪个功能在哪个入口」。

- 实现：`src/components/meeting-notes/CommandPalette.tsx`（cmdk，`shouldFilter={false}` 自管检索）
- 一次输入实时返回五类结果，按组图标区分：**会议标题**（前缀命中优先）、**转写内容**（每场取首个命中行 + 上下文摘录，回车跳转写页并精确选中该行）、**行动项**（含负责人 / 截止日 / 完成状态）、**决议**、**标签**（应用为列表筛选）
- 空输入显示最近会议；无结果时引导「语义搜索 / 直接问 AI」
- 全部为本地内存检索，零 AI 调用；关闭即卸载组件，下次打开输入框自动回到空态

## 四、渐进式披露与 AI 隐形化

**四层披露**（纪要页）：

1. 默认可见：一句话摘要 + 行动项 / 决议计数徽标（页签上）
2. 展开层：分议题要点卡片
3. 「详细层」折叠区：带时间戳转写全文（不经 AI 改写）
4. 调试 / 审计：事件日志（右栏「最近动态」）、支撑核验明细、忠实度报告

**AI 结果按原生内容呈现**：

- 摘要不贴「AI 生成」标签，只有用户改过的层标「已编辑 · 重新生成不覆盖」（`SummaryTab.tsx` 的 `LayerBadge`）
- 行动项只在**可能出错且需要核对**时标记：低置信（<0.75 且未编辑）用统一「待核对」语言——左侧橙色竖线 + 悬停「AI 建议，请核对」；弱支撑条目用琥珀色徽标（`ActionsTab.tsx` 的 `SUPPORT_META`）
- 漂移感知按**引用存活率**判定而非「转写改没改过」：转写在生成之后有改动时，核对该层结论的出处引用（摘要层用事实层 `facts[].sourceQuote`，抽取层用未确认行动项 / 决议的 `sourceQuote`）是否仍逐字存在于当前生效文本；缺失比例 ≥ 30%（`STALE_MISSING_RATIO`）才标「可能过时」——改错别字不会让全部结论降级，实质改写才会（`store.ts` 的 `layerStale` / `extractionStale`）；用户手改过的层是用户资产，永不标漂移

## 七、数据与 AI

- **存储（IndexedDB 为主档案）**：`lib/idbStore.ts` 两个 objectStore 分离——`meta`（会议元数据，剔除大文本）+ `chunks`（转写稿 / 清洗稿 / 整理前快照按 **48KB 分界**外置，UTF-8 字节边界分片 ≤800KB/片，zstd/lz4 逐片压缩）；增量写入按内容哈希比对，只落盘真正改动的部分。问答历史等小对象走 `kv` store
- **两阶段装载（分片恢复而非全量恢复）**：启动只读 `meta` + `kv`（同一事务内全部请求先发后等，消除逐条 await 的往返瀑布），列表与结构化字段立即可交互；外置大文本先以空串占位并返回 `pending` 清单，由 `hydrateMeetingFields` 后台**逐会**回填（选中会议优先，只填仍为占位的字段）。回填完成前落盘闸门关闭——否则占位空串会被增量写入误判为「用户清空」而删掉库内分片；导出备份同样等回填完成后再取最新快照
- **主线程税控制**：大分片（≥64KB）的 LZ4/deflate 压缩解压走文本 Worker（`textWorkerClient.compressChunkTask / decompressChunkTask`，超时/熔断自动回退主线程同步算）；zstd 归档层低频，留在主线程异步 wasm。落盘时机 = 400ms 防抖 + `requestIdleCallback`（5s 超时兜底，持续高负载下也保证最终写入）；保存时全部待重压字段跨会议并行压缩，压缩完成后才开单事务同步写盘
- **降级链与故障路径**：IndexedDB 打不开（无痕模式等）→ 回退 localStorage 单键整存；IndexedDB 写入抛错 → 兜底再写一次 localStorage，仍失败返回 false → 页面顶部挂红色横幅提醒立即备份（`storageError`），**不会静默丢数据**
- **写后读回校验（静默配额监控）**：事务 `oncomplete` 之后再用只读事务读回校验——meta 总条数必须等于内存会议数、最后写入的一条 meta 必须能读回；对不上即按写入失败处理（挂横幅引导立即备份）。防的是浏览器在存储压力下「事务报成功但数据被驱逐」的静默丢失
- **崩溃安全写入（先写意图，再写结果）**：关键操作（新建会议 / 生成纪要 / 抽取行动项 / 整理转写 / 导入备份）开始前，同步往 localStorage 写一条轻量意图标记（`lib/oplog.ts`）；结果经 `flushPersist` **立即落盘**（不等 400ms 防抖窗口，串行链保证写入顺序）并确认后清除标记。中途崩溃 / 关标签页 → 标记残留 → 下次启动扫描出恢复提示（琥珀色横幅，引导检查并重跑）。如实说明边界：标记只记「哪个操作可能没保存完」，不缓存 AI 产物本身（可达数 MB，localStorage 装不下）——恢复动作是「提示重跑」而非「自动还原」；配合立即落盘，真正的暴露窗口只剩「结果已进内存、IndexedDB 事务尚未提交」的几百毫秒
- **存储健康**：设置页显示**当前用量 / 浏览器预估上限 / 已用百分比**（`navigator.storage.estimate()`，环境不提供配额时隐藏占比行）、持久化状态（`storage.persisted`）；占比 ≥70% 琥珀色预警、≥90% 或超过 200MB 红色告警并提示归档低产出会议（归档区会议转写稿换用更高压缩分层）
- **健康面板（从日志到指标）**：设置页把三个既有日志源聚合成一屏运行状况——**AI 调用成功率**（账本 `ok` 占比）、**平均响应延迟**、**降级 / 整链失败频率与原因分布**（`lib/usageLog.ts`）、**存储用量趋势**（日粒度采样保留 35 天，`lib/healthLog.ts`，由落盘管线的配额估算顺带打点）、**语义索引重建频率**（手动重建打点）。不做实时刷新：面板随设置对话框挂载时计算一次，关闭即卸载、重开即重算，零常驻开销
- **设置类小数据**：Provider 配置、主题偏好、活动日志留在 localStorage（小、同步读、启动即用）
- **AI 管线**：`lib/ai.ts`（摘要 / 抽取 / 审查 / 消化 / 主题聚类 / 整稿翻译等全部 prompt 与调用）、`lib/llm.ts`（poll-first 调用契约）、`lib/providers.ts`（Provider 注册表：ASR / TTS / LLM / 翻译 / Embedding 五类，密钥本地保存）、`lib/translate.ts`（默认翻译引擎「大模型翻译」+ 统一门面，外部翻译引擎在此注册接管，ADR-0010）、`lib/agents.ts`（各环节 Agent 的模型与阈值配置）
- **成本控制**：所有付费调用先经确认对话框（`components/rh/CostConfirmDialog.tsx` + `lib/costConfirm.ts`）；用量记录 `lib/usageLog.ts`——**成功与失败都进账本**：整条降级链耗尽 / 鉴权失败经 `ai.ts` 的 failureRecorder 记 `ok:false` 条目（只记成功的话「成功率」永远是 100%，指标就成了摆设）
- **检索**：关键词 + 模糊容错（`lib/searchCore.ts`，Web Worker `search.worker.ts`）；语义向量（`lib/embeddingClient.ts` + `embedding.worker.ts`，transformers.js 本地推理，HNSW 索引）
- **问答 RAG 管线（先重排后摘要）**：`lib/ragPipeline.ts` —— **召回**（向量段级 Top-50：Worker 返回 `(meetingId, segIdx)` 命中，主线程用同一纯函数 `buildSegments` 重建段文本对齐；+ 词面通道：查询词 CJK bigram / 拉丁词元在头部字段与转写语义块上的命中密度）→ **重排**（RRF 名次融合两路排序，免疫量纲不可比；取 Top-5 场会议、每场 ≤2 个相关片段）→ **生成**（只有胜出会议的结构化头部 + 相关片段进 LLM 上下文）。相比旧版「全库直塞 80k 字符」，大档案下上下文缩一个数量级、噪音会议不再稀释注意力；≤5 场的小档案仍全量直塞（检索反而可能漏）。诚实说明：重排器是**轻量本地融合**（RRF + 词面密度），不是神经交叉编码器——浏览器内跑 cross-encoder 需再引入数十 MB 模型资产且每对 query×doc 一次前向，与「零费用离线」立场冲突；`rrfFuse` 是独立纯函数，将来换交叉编码器只动这一处
- **语义分块（chunk2 方案）**：`lib/semanticCore.ts` 的 `chunkTranscriptSemantic` 按话题边界切块——段落空行（补标点整理按话题分段产生）> 时间戳大间隔（≥120s）> 说话人轮换；块目标 ~420 字 / 硬上限 480 字（受 bge-small-zh 512 token 上下文约束，通用建议的 512-1024 token 在此模型上装不下，如实降档），块间重叠 ~70 字（落在建议的 50-100 token 区间）——检索命中的块是语义完整的讨论单元，不会「检索到半句话」。分段方案升级经 `SEGMENT_SCHEMA_TAG` 自动失效旧向量（等同换模型语义），下次同步后台重建，无需用户操作
- **引用级压缩与机器对账**：问答提示词要求每条关键结论附「最短支撑句」（≤60 字、逐字摘录、禁止整段照抄与改写拼接）；答案落地后 `verifyCitations` 把全部「」引文与上下文会议原文归一化对账（去空白标点、大小写无关），命中率徽标挂在问答记录上（全中绿色 / 有未对上琥珀色警示）——「引用是否真的在原文里」由机器核验，不靠人眼扫
- **问答自路由（按查询复杂度选策略）**：`lib/qaRouter.ts` 规则分类器在问答入口先判路由——结构化事实查询（谁负责 X / 某人未完成清单 / 截止日 / 决议清单 / 完成状态）**本地直答**：直接读行动项与决议字段作答，零费用、毫秒级、100% 忠实（不经模型就没有改写失真），不弹成本确认；综合类问题（含「为什么 / 演进 / 对比 / 趋势」等复杂标记）强制走完整 RAG。分类器保守设计：**模式命中且结构化数据里确有答案才直答，拿不准一律路由去 RAG**——误判代价是多等一次模型调用，不是错误答案。诚实说明：路由是规则而非小模型（意图类别封闭可枚举、零成本零延迟、判定可解释），未做「35-60% token 节省」的实测，节省幅度取决于提问里结构化查询的占比
- **评估台（机器能算的不让人打）**：golden set 固定「考卷」，重跑生成管线产出快照（`EvalBenchDialog.tsx` + `lib/evalRun.ts`）。三个**自动指标**随运行本地免费产出——引用校验通过率（忠实度代理：事实 source_quote 通过原文逐字对账的比例）、事实引用率（覆盖率代理：已核验事实被议题要点引用的比例）、遗漏候选数（遗漏自查同口径）；人工评估主路径是**对比判定**：与上一次运行的同场产出并排，点「本次更好 / 差不多 / 本次更差」三按钮即可，四维细打分保留为可选深度评估（默认收起）；运行支持**抽样 2-3 场**（随机抽样、多次运行轮换覆盖评估集，费用确认按实际场数）

### 备份与密钥（明确回答）

- 导出备份**默认不包含 Provider 密钥**，文件内显式标注 `secrets: excluded`，可安全分享
- 设置页导出区提供「包含配置」勾选框，勾选后文件标注 `secrets: included`，界面上明确警告「请勿发给任何人」（`SettingsDialog.tsx` + `store.ts` 的 `sanitizeProvidersConfig`：按 Provider schema 的 password 字段剔除；未注册 Provider 的配置保守整组剔除）
- 导入备份冲突策略三选一：merge（按会议合并）/ replace（整库替换）/ copy（副本导入），导入前有预览
- **备份版本契约**：备份根级带 `minReaderVersion` 字段；旧版本工具读到 `minReaderVersion` 高于自身 `APP_VERSION` 的备份时，在导入预览阶段优雅拒绝（「这份备份由更新版本导出…请升级后再导入」），不会解析到一半崩溃（`store.ts` 的 `backupVersionIssueOf`）
- **schema 迁移注册表（结构演进的主通道，ADR-0009）**：`lib/schemaMigrations.ts` 维护 `MIGRATIONS[N]` = vN→vN+1 的纯函数，导入时从备份自带 version 起**链式迁移**到当前版；宽容解析（`validateBackupObject`）降为最后防线，只兜「新增可选字段」这类天然兼容差异。当前 schema 仍是 v1（首版），注册表为空是正常状态——机制先行，第一次结构变更时开始积累。禁止跳版；断链如实停在断点（不硬解析）；`BACKUP_VERSION` / `APP_VERSION` 都引用 `SCHEMA_VERSION`，导出版本 / 迁移链终点 / 可读上限永远是同一个数
- **与档案加密的关系**：导出的备份文件**恒为明文 JSON**（加密只保护本机落盘数据，不进备份）——即便开启了档案加密，导出区也会显示琥珀色警示提醒「备份文件本身不加密」；导入备份走常规写盘路径，若已开启加密则自动以密文落盘（详见下方「安全与隐私」）

### 语义索引的一致性（明确回答）

- 向量记录持久化在独立 IndexedDB（Worker 内），每条带 `{ meetingId, stamp, model }`：`stamp` 是内容戳（增量构建的脏标记，会议未变不重算），`model` 是 embedding 模型 ID
- **换模型自动失效**：检索时跳过 `model !== SEMANTIC_MODEL_ID` 的旧向量（`embedding.worker.ts`），重建时覆盖写入——旧索引不会污染新模型的结果
- 会议增删改 → 对应记录标记脏 → Worker 后台增量重建；索引损坏或不一致时以主数据为准，设置页「重建索引」全量重算

### 事件日志（明确回答）

两层，职责不同：

- **活动日志**（右栏「最近动态」）：append-only 但有硬上限——`ACTIVITY_CAP = 100` 条，读写两侧都截断（`store.ts` 的 `loadActivity` / `saveActivity`），不会无限增长
- **事件日志 / 会议历史**（`lib/eventJournal.ts`，顶栏时钟按钮打开）：event-sourcing-lite——所有会议字段变更以**带前后值的差异事件**追加记录（`patchMeeting` 自动记、AI 生成管线带标签记、创建/删除/归档记信息事件），支撑三个能力：**变更时间线**（每场会议的字段级前后对照）、**条目履历**（追踪单个行动项/决议从提出到完成的全部状态变化，含已删除条目）、**时间点回滚**（「回到此时间点之前」= 逆向重放该时刻之后的全部事件）。诚实说明边界：① 这不是完整事件溯源——当前状态**不由**事件重放派生（重写存储层对单机工具风险/收益不成比例），主状态仍是会议对象，日志是叠加的审计层；② 大文本字段（转写稿 / 清洗稿，单值 >6000 字符）只记长度不记内容，含大文本变更的时间段不可回滚（存储体积考量，按钮如实禁用并说明）；③ 回滚是整体的——区间内任一事件不可回滚就不提供部分回滚（半新半旧的拼接状态比不回滚更糟）；④ 每场会议滚动保留 80 条事件、全局 2000 条，localStorage 独立键，写失败静默降级（日志尽力而为，绝不阻塞业务写入），不随备份导出（备份契约不变）；⑤ 连续击键类变更（转写输入）60 秒窗口内合并为一条事件，不淹没有意义的操作

### 安全与隐私：静态加密 / 安全删除 / 密钥轮换（明确回答）

**档案加密（可选的静态加密，`lib/vault.ts` + `lib/vaultOps.ts` + `VaultGate.tsx` + 设置页「隐私与安全」）**

- 威胁模型（如实）：防的是**本机静态数据被第三方读取**——同设备的其他浏览器扩展、本地恶意软件、共享电脑上的其他用户直接翻 IndexedDB / localStorage 文件。**不防**：解锁后内存中的明文（运行时必然）、浏览器进程本身被攻破、以及**忘记密码**（无后门、无找回，密码丢了加密档案永久不可读）。适合处理法务 / HR / 战略等敏感会议的用户在共享设备上启用
- 密码学：Web Crypto 原生，零外部依赖——`PBKDF2(密码, 随机 16B 盐, 21 万轮, SHA-256)` 派生 `AES-GCM 256` 会话密钥；每条记录随机 12B IV，密文 = `iv‖ciphertext`，GCM 自带完整性校验（篡改即解密失败）。会话密钥 `extractable=false`、**只在内存**，刷新页面即丢弃 → 每次打开工具都要重新输密码
- **记录级自描述加密**：密文记录带 `enc` 标记（IndexedDB 四类 store：meta / chunks / kv / searchIndex），密文 blob 带 `{vault:1}` 信封（localStorage 内容型键，见 `vault.ts` 的 `REGISTERED_BLOB_KEYS`）——明文与密文可共存。开启 / 关闭 / 改密都是「逐条重加密」的可中断操作，中途被打断数据依然可读，重跑即收敛（不存在「一半数据永久锁死」）
- **加密范围**：IndexedDB 全部会议数据（转写稿等大文本分片**先压缩后加密**）+ 问答历史 + 检索索引；localStorage 的活动日志 / 事件日志 / 修正日志 / 评估快照 / AI 账本 / Provider 配置（含 API 密钥）/ 模板 / Agent 指令 / 实体别名。**不加密**（如实列明）：应用设置 / 健康采样 / 主题（纯配置与数字指标，无会议内容）、平台登录态（属平台管辖）、语义向量库（Worker 内独立 IndexedDB，向量是转写稿的衍生数据——极高机密场景建议先关语义检索）
- **localStorage 同步 API ↔ Web Crypto 异步 API 的桥**：读永远同步（解锁时 `refreshBlobCache` 一次性把全部 blob 明文预热进内存缓存），写先进缓存、后台串行队列加密落盘（毫秒级；关键流程 `await flushVaultWrites()` 确认）。`VaultGate` 在解锁前**挡住整棵应用树**——所有领域 hook、localStorage 读取、AI 调用都发生在解锁之后
- **开启加密后 IndexedDB 成为强依赖**：无痕模式 / IDB 被禁时拒绝 localStorage 降级（降级路径的异步密文持久化无法维持「写入失败绝不静默」的强一致口径），如实挂横幅。**备份文件本身不加密**（加密只保护本机落盘数据），导出区在开启态显示琥珀色警示

**安全删除（尽力而为的覆写 + 如实告知）**

- 删除会议时（`idbStore.secureDeleteMeetingRecords`，由 facade 的 `removeMeeting` 触发）：先用**等长随机字节覆写**这场会议的全部分片 / 元数据 / 检索索引记录，再删除——覆写早于 400ms 防抖落盘的逻辑删除发生
- 如实边界：**浏览器无法从 JS 擦除物理扇区**，IndexedDB / localStorage 的删除是逻辑删除，旧字节可能残留在底层存储引擎文件里直到 compaction。覆写显著降低「从磁盘直接翻出已删内容」的可能，但**不构成保证**——共享设备上的根治办法是开启档案加密（盘上只有密文，删除即失去可读性）。删除确认按钮与设置页「安全删除」区都明确写出这一点
- 设置页「隐私与安全」另有**彻底清空本机数据**：覆写并删除应用前缀内的全部 localStorage 键（含 vault 元数据）+ 删除主库与语义向量库两个 IndexedDB，用于归还共享设备 / 销毁档案（平台自身的键——登录态、费用确认记忆——绝不触碰）

**密钥轮换与撤销（本地场景的正确原语）**

- **Provider 密钥轮换卫生**（`providers.ts` 的 `setProviderConfigValue`）：password 类字段被替换前，先用**等长随机串覆写旧值写一遍**再写新值，尽力抹掉旧密钥在存储介质上的残留。如实边界：localStorage 的 setItem 逻辑上替换整值，物理扇区是否即时擦除由浏览器决定，这是最佳努力；开启档案加密后旧密钥本就以密文落盘、整 blob 每次用新随机 IV 重加密，残留面进一步收敛
- **档案密码修改 = 本地场景的「密钥撤销」**（`changeVaultPassword`）：全量数据按新密码派生的新密钥重加密，**旧密码派生的旧密钥即刻失效**——不存在「旧密码还能解开」的残留。如实风险窗口：重写进行中强杀页面可能留下「新钥密文配旧钥元数据」（不可读），UI 明确提示「过程中勿关闭页面 + 建议先备份」，中断后的稳妥恢复路径是「用当前密码关闭加密 → 重新开启」
- **设备撤销不在范围内**（如实说明）：本工具是 local-first、**没有跨设备同步后端**——备份靠手动导出 JSON / 导入，不存在「设备注册表」或可远程吊销的会话。因此「撤销某设备的访问权限」在当前架构下无对应原语；跨设备场景的等价能力就是「换档案密码」（旧密钥失效）+「备份默认不含密钥」。若将来引入同步后端，设备撤销的地基是每台设备一把包裹密钥（wrap key）+ 服务端吊销列表，届时再建

## 十、开发

```bash
pnpm install
pnpm dev        # 开发服务器（默认 8000；端口被占用时 Vite 自动顺延）
pnpm build      # tsc -b && vite build
pnpm lint       # eslint
pnpm golden     # golden set 回归（node scripts/golden-set.mjs）——升级依赖 / 改 schema 后的最低验证门槛
```

> Windows 一键启动：双击根目录 `start.cmd`（自动探测 8000+ 空闲端口、依赖缺失时先 `pnpm install`、并打开浏览器；窗口报错时保持打开便于排查，不会闪退）。

依赖治理：全部依赖在 `package.json` 锁为**精确版本**（无 `^`/`~`，精确版本号即「最后验证版本」，`lastVerified` 字段登记日期）。升级流程（一次一个 → golden set → tsc/eslint/build）、冻结清单、明确不做的方向见 `docs/freeze-list.md`；关键决策的来龙去脉见 `docs/adr/`；依赖审计（pnpm audit 归属 + bundle 组成 + 未使用依赖）见 `docs/dependency-audit.md`。

### 治理文档一览

- **golden set**（`scripts/golden-set.mjs`，`pnpm golden`）：升级依赖 / 改 schema 后的最低验证门槛，50 条断言覆盖数据不丢不错的全部命门——schema 迁移链（含断链 / 抛错 / 未来版本）、备份导出导入保真、大文本分片 + 压缩的存储往返（1.8MB 转写稿字节级一致）、四种压缩编解码器、事件日志 patch→回滚、档案加密全生命周期（开启 / 锁定态密文 / 错密拒绝 / 改密旧密失效 / 关闭回明文）、安全删除。用 fake-indexeddb + vite ssrLoadModule 直跑 `src` 的 TS 源码，Node 无 Worker 时走 textWorkerClient 同步回退（与浏览器同一套编解码实现）
- **ADR 决策记录**（`docs/adr/`，9 篇 + 索引 + 模板）：固定四段「背景 / 决策 / 考虑过的替代方案 / 何时重新评估」，永不改写历史（决策变了新增一篇、旧的标「被取代」）。覆盖：0001 存储架构（IDB 为主）、0002 分片压缩双分层、0003 RRF 重排（含「不是交叉编码器」的诚实说明）、0004 LLM 调用降级链、0005 prompt 三铁律、0006 置信度阈值体系（0.85/0.75/0.5/0.7/0.6 每个数的来历）、0007 档案加密参数（PBKDF2 21 万轮的取舍）、0008 事件溯源-lite、0009 备份兼容双轨制
- **冻结清单**（`docs/freeze-list.md`）：三档管理——**冻结**（图谱 / 评估台 / 命令面板 / 用量面板 / 健康面板：不主动排期增强，安全与正确性修复照做）、**维护模式**（时间线 / 会议历史 / 决议 / 行动项 / 摘要 / 问答 / 转写：只修 bug，调参须评估台数据支撑）、**明确不做**（多人协作 / 云同步账号 / 移动原生 / 浏览器训练模型 / 自研存储 / 插件系统 / 神经交叉编码器）。每项带可观测的解冻触发条件；解冻必须留痕（清单登记一行「为什么」+ 涉及架构变更补 ADR）

约定：领域 hook 通过参数注入依赖（meetings / setMeetings / agentModel / costConfirm…），只拥有自己域的状态；facade 只做组合与 re-export（`SupportSummary`、`DigestRow` 等类型随域迁移后从 facade re-export，消费方导入路径不变）。跨域共用的资源显式注入而非各自持有：`meetingsRef`（会议数据快照 ref）与 `askRunningRef`（问答 / 语义找会共用的检索类调用锁）由 facade 持有，注入给需要的域；`qaHistory` 归存储域（facade）持有——它随主库持久化、随备份导入导出——问答域注入读写。所有 AI 调用必须过成本确认；数据操作不可变更新（`setMeetings(prev => …)`）。
