# ADR：架构决策记录（Architecture Decision Records）

这里记录本工具**关键决策点的来龙去脉**——不是代码注释的复述，而是「当时为什么这样选、
考虑过哪些替代方案、什么情况下应该重新评估」。代码会腐化，记忆也会；三个月后回来看
某个阈值或某条降级链，先来这里找答案。

## 约定

- 一个决策一个文件，编号递增，**永不改写历史**：决策变了就新增一篇并把旧篇状态改为
  「被 ADR-XXXX 取代」；
- 每篇固定四段：**背景 / 决策 / 考虑过的替代方案 / 何时重新评估**；
- 状态只有三种：`已接受` / `被取代` / `已废弃`；
- 改代码时如果动了某篇 ADR 记录的常量、顺序或契约，**同一提交里更新那篇 ADR**
  （至少更新「何时重新评估」的触发情况是否已发生）。

## 模板

```markdown
# ADR-XXXX: 一句话决策标题

状态：已接受（YYYY-MM）

## 背景
（当时面对的问题、约束、压力——写清「不决策会发生什么」）

## 决策
（选了什么，关键参数/顺序/契约原样列出，标注代码锚点文件）

## 考虑过的替代方案
（每个方案一行：是什么、为什么没选）

## 何时重新评估
（可观测的触发条件，不是「以后再说」）
```
