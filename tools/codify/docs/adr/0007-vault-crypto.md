# ADR-0007: 档案加密参数——PBKDF2-210k + AES-GCM，记录级自描述，无后门

状态：已接受（2026-09）

## 背景

local-first 工具的静态数据（IndexedDB / localStorage 文件）对同设备其他扩展、
本地恶意软件、共享电脑其他用户是明文可读的。处理法务/HR/战略会议的用户需要
「盘上不是明文」。约束：纯浏览器、零外部依赖、零服务端（没有地方托管密钥），
且不能引入「忘了密码就锁死一半数据」的脆弱状态。

## 决策

`src/lib/vault.ts` + `src/lib/vaultOps.ts`，全部用 Web Crypto 原生原语：

- **密钥派生**：PBKDF2(密码, 随机 16B 盐, **210,000 轮**, SHA-256) → AES-GCM 256 会话密钥。
  210k 轮对齐 OWASP 2023 对 PBKDF2-SHA256 的推荐下限，在「抗暴力破解」与
  「解锁派生 < 1s 用户体验」间取平衡；
- **密钥只在内存**：会话密钥 `extractable=false`（不可导出，减少内存转储面），
  绝不落盘；刷新/重开工具都要重新输密码——「每次打开需要密码」是设计目标不是缺陷；
- **密码校验**：verifier = 用派生密钥 AES-GCM 加密一段固定明文，解锁时解密比对——
  不在盘上存密码哈希（存了就成了离线爆破靶子）；
- **每条记录随机 12B IV**，密文 = iv‖ciphertext（同明文每次密文不同）；
- **记录级自描述加密**：每条 IDB 记录 / 每个 localStorage blob 自带「是否加密」标记
  （`enc` 字段 / `{vault:1}` 信封），密文明文可共存——开启/关闭/改密的中途被打断，
  数据依然可读，重跑即收敛，**不存在「一半数据永久锁死」的状态**；
- **顺序契约**：开启=先写 vault 元数据再逐条重加密（混合态可读）；关闭=先重加密回
  明文再清元数据（反序会把密文搁浅在无钥状态）；改密=全量解密旧钥/加密新钥后
  原子换 sessionKey+元数据；
- **无后门、无找回**：密钥由密码派生，密码丢了数据永久不可读——开启前需勾选确认。

## 考虑过的替代方案

- 存密码哈希做校验：等于给离线爆破留靶子，verifier 加密比对更安全；
- 全局单密钥加密整库：一处损坏全库不可读，且无法做「中途可打断」的渐进重加密；
- 密钥落盘（哪怕加密存储）：浏览器里没有比用户密码更根信任的密钥来源，落盘即破功；
- 用 PBKDF2 更高轮数（如 600k）：解锁派生逼近 2-3s，体验劣化，而 210k 对
  「本地设备已被攻破」这一威胁模型的边际收益有限——真正的防线是设备安全；
- Argon2id（更抗 GPU 爆破）：Web Crypto 原生不支持，需引 wasm 依赖，与零依赖立场冲突。

## 何时重新评估

- Web Crypto 原生支持 Argon2id，可替换 PBKDF2 提升抗爆破强度；
- OWASP 上调 PBKDF2-SHA256 推荐轮数（届时随一次改密流程把 iter 提上去，
  verifier 与全部记录重加密）；
- 威胁模型变化：若引入云同步，密钥管理需重新设计（当前「密码即根信任」不适用于多设备）。
