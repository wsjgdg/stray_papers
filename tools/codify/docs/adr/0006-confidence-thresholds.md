# ADR-0006: 置信度阈值体系——0.85 / 0.75 / 0.5 / 0.7 / 0.6 各自的来历

状态：已接受（2026-09）

## 背景

多处需要「模型/规则给一个把握程度，低于某线就交人工」。如果各拍各的数，
既无法解释也无法统一调参。这里把每个阈值的语义和来历钉死，避免三个月后
对着一个 0.75 发呆。

## 决策

阈值按「信号强度」分三档，全局一致：

- **0.85 = 强信号，可直接采信**：
  - 说话人规则一「行内自我介绍（我是X/我叫X）」给 0.85（`speakers.ts`）——
    自我介绍是显式声明，几乎不会错；
  - 保真度：整理稿与原文整体相似度 < 0.85 判「疑似大量改写」（`fidelity.ts`）——
    整理只该动标点/分段/错别字，实质内容相似度理应极高，跌破 0.85 说明改多了；
  - 转写去重：8-gram 相似度 ≥ 0.85 判重复（`textPure.ts`）——同一场会重复导入。
- **0.75 = 中等信号，采但标注来源**：
  - 说话人规则二「上一行称呼了X → 这条应答大概率是X」给 0.75——称呼-应答是
    强语用线索但非显式声明，留一档余地。
- **0.5 = 弱信号，必落「待确认」**：
  - 说话人规则三「公开邀请应答后，除提问者外恰好一位已知说话人」给 0.5——
    应答者身份是推断出来的，多人场景直接不猜（宁漏不错）。
- **UI「待确认」线 = 0.6**（`speakers.ts` 注释）：confidence < 0.6 的建议默认
  **不勾选**且标「待确认」——0.5 的弱信号必然落进这里，需用户手动确认才生效。

Human-in-the-Loop 复核门槛按角色分（`agents.ts`，可被用户覆盖）：

- **extract（结构化抽取）reviewThreshold = 0.7**：抽取的行动项/事实会直接进档案
  被执行，容错成本低——低于 0.7 扣进「待人工确认」队列，不直接生效；
- **annotate（说话人标注）reviewThreshold = 0.6**：标注错了改起来轻（就是改个名字），
  容错成本高——门槛放到 0.6，与 UI 待确认线对齐；
- **summary / retrieve reviewThreshold = 0**：产出即结果、无处可扣（摘要没有「半生效」态），
  字段保留为 0。

## 考虑过的替代方案

- 全部统一一个阈值：抽取和标注的容错成本差一个量级，一刀切要么放漏错误行动项、
  要么把无害的标注错误也拦下来增加人工负担；
- 阈值写死不可调：不同用户的风险偏好不同，`agents.ts` 的 reviewThreshold 暴露为
  可配置（0 = 不扣、沿用低置信标注）；
- 用模型 logprob 当置信度：平台网关不回传 logprob，且跨模型不可比——规则信号
  （自我介绍/称呼/邀请）的置信度是人工标定的语义强度，比伪 logprob 诚实。

## 何时重新评估

- 评估台积累足够样本后，用实际精确率/召回率反推阈值（当前是语义标定的经验值，
  不是统计最优）；
- 说话人推断接入声学特征（声纹）——0.5 的语用推断可被更强的声学信号取代；
- 用户反馈某类误拦/误放集中出现，调对应角色的 reviewThreshold。
