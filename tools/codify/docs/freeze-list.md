# 冻结清单 & 维护公约（Stop-Optimizing List）

> 所有长期维护的个人项目，最终都死于「永远在优化，永远没稳定」。
> 这份清单的作用不是限制，而是把精力钉在真正重要的地方。
> 没有冻结清单的项目，会在半年后变成一堆半成品功能的堆砌。
>
> 最后更新：2026-09-26 · 复议节奏：每季度末过一遍，改动需在此登记一行「为什么解冻」。

---

## 一、依赖升级公约（先于一切功能）

**已锁定**：`package.json` 全部依赖为**精确版本**（无 `^` / `~`），精确版本号即
「最后一次通过全套验证的版本」；`package.json` 顶层 `lastVerified` 字段登记验证日期。

**升级流程（铁律，禁止批量升级）**：

1. 一次只升**一个**依赖（改 package.json 里那一行）；
2. `pnpm install` 后跑 `node scripts/golden-set.mjs`（golden set，覆盖数据不丢不错的
   全部命门：schema 迁移 / 备份保真 / 存储往返 / 压缩 / 事件日志回滚 / 档案加密 / 安全删除）；
3. 再跑 `./node_modules/.bin/tsc -b`、`./node_modules/.bin/eslint src`、`./node_modules/.bin/vite build`；
4. 全绿 → 更新 `lastVerified.date`，提交信息写明「升级 X a→b，golden set N 条断言通过」；
5. 任一红灯 → **停止**，先定位是依赖破坏还是套件自身过期，绝不带着红灯升下一个。

**重大版本升级**（React / Vite / Tailwind / transformers.js 跨大版本）额外要求：
升级前在 `docs/adr/` 补一篇「为什么现在升、迁移了哪些 breaking change」，
升级后人工过一遍 golden set 覆盖不到的视觉/交互路径（首屏、问答、图谱、评估台）。

依赖现状审计见 `docs/dependency-audit.md`（含未使用依赖、bundle 组成、漏洞归属）。

## 二、以下功能【冻结】——够用了，不再优化，只接受安全/数据正确性修复

| 功能 | 冻结理由 | 解冻触发条件 |
| --- | --- | --- |
| 图谱可视化（GraphTab） | 关系探索已达「能看清人物/议题关联」的够用线，再加力导/筛选是边际递减 | 用户反馈图谱在 >200 实体时不可读（性能，非功能） |
| 评估台（EvalBenchDialog） | golden set 机制已固化，评估台是手动补充，不需要更多自动化 | 评估台自身出现数据丢失/误判 bug |
| 命令面板（CommandPalette） | 键盘全流程已覆盖高频动作，命令集稳定 | 新增的功能页需要对应命令入口（跟随功能，非独立优化） |
| 用量面板（UsagePanel） | AI 调用账本已能回答「花了多少、花在哪」，无需更多图表 | 计费口径变化导致账本数字失真（正确性） |
| 健康面板（SettingsDialog 内） | 配额可视化 + 指标已达「出问题能自查」的够用线 | 存储后端变化（见 ADR-0001）导致指标口径失效 |

冻结 ≠ 不许碰。冻结的准确含义：**不主动排期做增强**；出现安全漏洞、数据损坏、
正确性 bug 时照常修，修完不需要「顺便优化一下」。

## 三、以下功能【维护模式】——只修 bug，不加功能

| 功能 | 维护边界 |
| --- | --- |
| 时间线（TimelineTab） | 事件日志驱动的会议内时间线已完整；只修回滚/履历的正确性 bug |
| 会议历史（MeetingHistoryDialog） | 时间点回滚 + 条目履历已达 ADR-0008 的设计边界；只修数据一致性 bug |
| 决议（DecisionsTab） | 决议的抽取/编辑/关联已够用；只修抽取错误 |
| 行动项（ActionsTab / DueTab） | 行内快速操作 + 智能排序 + 到期跟进已完整；只修状态机 bug |
| 摘要（SummaryTab / PreMeetingBrief） | 分层摘要 + 会前简报的 prompt 已按 ADR-0005 三铁律固化；只修编造/格式失败 |
| 问答（QATab） | RAG 管线（ADR-0003）已重构完成；只修引用对账/召回错误，调参走评估台不走手改 |
| 转写（TranscriptTab） | 清洗/标点/说话人标注管线已固化；只修内容被误改（保真度）bug |

维护模式的准确含义：**功能面不再扩张**；bug 照修，阈值/参数调整必须有评估台
数据支撑（见 ADR-0006「何时重新评估」），不凭手感改。

变更登记：2026-09-26 解冻「转写（TranscriptTab）」一次，因为用户点名要求
「翻译作为独立服务商类型」（触发条件 = 用户直接决策）。范围严格限定为
旁路能力：译文存独立副本层 `meeting.translation`，不触碰清洗/标点/标注管线，
不改变保真契约；Provider 注册表与 Agent 体系随之扩一类（ADR-0010）。
登记后转写页回到维护模式，本条不构成后续功能扩张的先例。

## 四、以下方向【明确不做】——写下来是为了将来不再反复讨论

| 方向 | 为什么不做 |
| --- | --- |
| 多人协作 / 实时协同编辑 | 与 local-first 单机定位根本冲突；引入 CRDT/服务端即不再是「个人会议档案工具」（见 ADR-0008 多设备触发条件，那是同步不是协作） |
| 云端同步 / 账号体系 | 当前威胁模型与密钥设计（ADR-0007「密码即根信任」）不适用多设备；做同步要先重设计密钥管理，是另一个产品 |
| 移动端原生 App（iOS/Android） | 本工具是桌面浏览器工作台；原生 App 是独立项目，不在此仓库范围 |
| 在浏览器里训练 / 微调模型 | 超出 Web 应用边界，算力与资产体积都不现实；只用现成推理（本地 wasm embedding + 平台 LLM） |
| 自研数据库 / 存储引擎 | IndexedDB 够用（ADR-0001）；自研存储是拿唯一数据源冒险 |
| 插件系统 / 第三方扩展 API | 单人工具引入扩展点 = 引入无限兼容负担；需要的能力直接内建 |
| 神经交叉编码器重排（当前） | 数十 MB 模型资产 + 每对前向，与零费用离线立场冲突（ADR-0003）；留作 rerankChunks 单点替换的未来选项，不进主线 |

「明确不做」的准确含义：**不投入实现**；但每篇相关 ADR 的「何时重新评估」里
留了触发条件——条件真发生时，回来把这条从「不做」移到「维护/冻结」并登记理由。

## 五、决策变更留痕

解冻任何一个冻结项、或把任何「不做」方向拉回主线，都要：

1. 在本文件对应表格加一行「YYYY-MM-DD 解冻 X，因为 <可观测的触发条件已发生>」；
2. 若涉及架构/参数/契约变更，在 `docs/adr/` 新增一篇 ADR（不改写旧 ADR，旧的标「被取代」）；
3. 提交信息引用本文件与 ADR 编号。

没有留痕的解冻 = 偷偷优化 = 半年后半成品堆砌的开始。
