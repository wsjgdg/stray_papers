## 第八轮：Edge 朗读静音修复（ConductorPanel.tsx `speakMsg`）
- 症状：用户 Edge 中点「朗读」**无声且无报错**，已证实本机有 17 个中文 voice（非缺语音包），`voiceVolume` 默认 1（非音量=0）。`auxView(m.text).shown` 文本非空、按钮正常。成因锁定 **Edge/Chromium `speechSynthesis` 静默 bug**：`cancel()` 后同步 `speak()` 被吞、`synth` 偶发卡 `paused` 态、`onerror` 不触发。
- 防御（三重）：
  1. `speak()` 前若 `synth.paused` 先 `resume()` 解锁；
  2. 改用 `requestAnimationFrame` 异步帧触发 `speak()`，避开 cancel→speak 同步吞字；
  3. 看门狗：`u.onstart` 置 `started` 标志；300ms 后若 `!started && !synth.speaking && !synth.pending` 则 `resume()`+`speak()` 重试一次。
- 竞态补丁：`speakTokenRef` 令牌（每次调用含停止自增），已排程的 rAF/看门狗检查 `speakTokenRef.current !== myToken` 即作废，**防止停止后旧排程又重新朗读**。

## 第九轮：TTS 静音真因——`loadVoiceVol()` 返回 0（非 paused-state bug）
- 第八轮 paused-state 三重防御**仍静音**（用户 Edge 实测）。重新逐值排查，发现真因在 `src/lib/voiceVolume.ts:loadVoiceVol()`。
- **根因**：`Number(window.localStorage.getItem(KEY))` 当 key 不存在时 `getItem` 返回 `null`，而 **`Number(null) === 0`**（不是 NaN）。于是 `Number.isFinite(0)` 为真 → 返回 `Math.min(1,Math.max(0,0)) = 0`。即**未存过音量时默认 0 → 朗读音量恒为 0 → 静音且无报错**。第七/八轮"默认 1"的判断是**错的**（`Number(null)` 求值陷阱）。
- 对比 `loadTtsPrefs()` 正确（`raw ? JSON.parse(...) : {}`，null 走默认对象），故语速/音高无此问题。
- 修复：`loadVoiceVol()` 显式 `if (raw === null) return 1;` 再 `Number(raw)`。仅 SoundPanel 滑杆 `onChange` 调 `saveVoiceVol`，无初始化写入 → 未动过滑杆的用户 localStorage 为 null → 现返回 1。
- 第八轮的 rAF/resume/看门狗防御保留（无害，对真 paused 态仍有用），但主因是音量。
- 验证：`npm run build` 通过（EXIT 0）。需用户 Edge 重新双击 `start.cmd` 启动后点「朗读 ♪」复核（**注意：若本机 localStorage 已存过 `so-voice-v1=0` 需清空或把听感滑杆拉到 >0**）。
