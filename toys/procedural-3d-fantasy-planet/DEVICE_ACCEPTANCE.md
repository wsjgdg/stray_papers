# Aetheris 真机验收清单 · pennants-81

> **状态：待真人在真实设备上执行。** 自动化使用的是 Chromium / SwiftShader 和模拟触屏，不能代替人眼、耳朵或设备 GPU 的结果。这里是操作步骤，不是已经通过的验收报告。

## 准备与记录

1. 使用对话中的 **8080 预览**（或自行部署的同一版本）在真实浏览器打开。首次加载需要能访问 three.js CDN；等待加载完成。不要使用浏览器的手机模拟器代替手机，也不要为了跑分隐藏物体、暂停动画或关闭场景。
2. 记下设备型号、操作系统和浏览器版本、屏幕方向、是否开启省电/低电量模式，以及网络是否正常。可在桌面控制台执行 `window.aetheris.diagnostics().build`，或在下面的性能 JSON 中检查 `build` 是否为 `pennants-81`。
3. 默认先用 `AUTO` 画质和默认抗锯齿；正常亮度、音量和输入方式。尽量在同样位置、画面方向及温度下比较，并记下画质是否自动改变。屏幕录制和其他应用会有开销，性能记录时不要额外录屏；需要录屏复现画面或操作问题时请注明。
4. 每项结果写 **通过 / 失败 / 未测**，注明实际看到或听到什么。无法制造场景不等于通过；真机意见和异常截图、短视频可与性能文件一起反馈。

## 画面与操作

- [ ] 启动、轨道旋转和缩放正常，无黑屏、大片缺失、明显闪烁或长期卡在加载页。切换日夜、天气后仍能辨认地形、云海和三座浮空城。
- [ ] 打开「浮空城」入口或野档中的 THREE CITIES，分别近观 VIRE、SOLEN、KEST，旋转/缩放后返回星球。它们是不可登陆的缩尺模型，不要按完整城市关卡验收。
- [ ] 降落至地表后，正常行走、转向、跳跃/下蹲，碰撞的墙和石头确实阻挡；走出建筑、越坡、进出海岸没有突然传送或持续卡住。桌面按住 `H` 隐行时才可穿过物体，松开后恢复碰撞；地面始终托住人。
- [ ] 手机分别在竖屏和横屏检查摇杆、拖动视角、跳跃/下潜、返回轨道、野档及画质按钮能点中，不互相覆盖。切换方向后画面没有偏移。手机不要求使用没有提供的键盘 `H`。
- [ ] 野档与地图可打开、滚动、关闭，画质按钮按 `AUTO → LOCKED HIGH → LOCKED BALANCED → AUTO` 切换；观察实际档位和观感，不把档位标签当作帧率。

## 图鉴遮挡

- [ ] 在图鉴尚未记录某种动物的情况下，先确认其真实位置：如果动物完全在建筑墙体或山脊后且自身处在识别范围和视角内，等待至少一次扫描，不应凭空解锁；移到能看见其身体的无遮挡位置并对准后，应可解锁。动物会移动；若无法同时确认目标、范围和遮挡，请记为**未测**而非通过。
- [ ] 能够找到可见的浮幡、巡管虫或驮园时，分别尝试向上看和水下视线；水面本身不应被当作不透明地面。各省虫群是进入相应省份自动记录的氛围条目，不属于上述实体视线判断。
- [ ] 如出现疑似误识别或始终无法识别，提供切换遮挡前后的短视频、对象名称、所在场景/位置和操作。当前建筑使用实际建筑实例三角形；地形是高度场沿线采样，不宣称覆盖植被、全部动态物体或每个小于采样间距的细节。

## 声音与剧情

- [ ] 用户主动点按扬声器按钮或按 `M` 开声；检查环境声、脚步、碰撞声，在水边/水中或动物附近可观察相应声音，调节音量后无爆音或持续破音。手机还需检查静音开关、媒体音量和浏览器自动播放限制。听不到时先区分系统静音、标签页静音和页面声音按钮。
- [ ] 如选择验收剧情：见证作业、巡管虫提示和扫描，检查地图标记；错音进度刷新后仍在，野档中的「重置本机剧情进度」只在确认后清除本机剧情。另一个浏览器或设备不会自动同步。无时间完整触发时记为未测。

## 真实性能：分别采集轨道与地表

1. 进入要测试的场景，打开右上角 **野档**，找到 **DEVICE PERFORMANCE · 设备性能记录**，点「准备 20 秒记录」。
2. 关闭野档。等按钮角标显示 `REC`，保持页面在前台，在轨道正常旋转，或在地表正常行走与转视角；不要打开野档/地图、切后台或人为隐藏物体。角标显示「完成」后再打开野档。
3. 点「下载 JSON」保存；下载受限时点「显示 JSON」，全选复制保存。把轨道和地表分别记为 `orbit`、`ground`，各采一次；严重卡顿或波动时按相同步骤再采一次。若打开面板、切后台或图形上下文丢失导致中断，报告会标注 `interrupted`，应重新采集；不以部分数据冒充完整样本。
4. 在 JSON 中查看 `build`、`environment.gpu`、画布尺寸/像素比、各帧 `tier`、`summary.rafIntervalMs` 和 CPU 阶段时间。若支持 GPU 时间查询，也会有少量 `gpuElapsedMs` 样本与 `gpuTimer` 的跳过/丢弃数；不支持或样本稀少时不要填造数值。
5. `RAF` 间隔是浏览器回调间隔，**不是实际显示帧或呈现时间**；它是上一次回调到本次回调的间隔，而同一条记录中的阶段时间属于本次回调，不能直接视为同一帧的因果。`renderCallWallMs` 不是 GPU 完成时间。GPU 查询仅覆盖提交的 WebGL 工作，不包含完整合成器/显示链，也有采样开销；开启 bloom 时 draw calls/三角形计数可能只是最后一个后处理 pass。画质自动改变、设备降频、其他应用和浏览器调度都会影响结果。目标 60 FPS 是设计目标，不是这次已验证的承诺。
6. 若需要定位抗锯齿影响，可另行用 URL 的 `?aa=on` 与 `?aa=off` 各刷新并重复同一路线，保留两个文件，注明边缘画质的变化；实际开启与否以 JSON 中 `antialiasActual` 为准。这是额外对照，不替代默认设置的记录，也不应更改场景或碰撞。

性能报告只存在当前标签页，不会自动上传；刷新或准备新记录会覆盖/清除。它包含采集时间、浏览器标识、GPU 名称、窗口/画布尺寸和游戏画质等信息，不包含网址、IP、现实位置或剧情存档。分享前请自行查看内容。
