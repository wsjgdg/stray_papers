# 菜品照片投放说明

把图片放进这个目录（`public/dishes/`），**文件名里带上菜名**，然后跑一次 `npm run photos`，
详情面板就会自动把「口味卡面」换成照片。没放图的菜保持口味卡面，不会裂图。

图片随前端本地打包，**不引用任何外链图床**（Wikimedia 等在国内不可达，实测 `upload.wikimedia.org` 直接 000），
所以用户端不依赖任何境外 CDN。

## 命名规则

- ✅ `麻婆豆腐.jpg`
- ✅ `四川-麻婆豆腐.jpg`
- ✅ `mapo-tofu-麻婆豆腐.webp`
- ❌ `IMG_2043.jpg`（认不出是哪道菜，会被跳过并在控制台提示）

支持 jpg / jpeg / png / webp / avif。建议横图、宽度 ≥ 800px、单张 ≤ 300KB。

## 署名（可选但建议）

新建 `credits.json`：

```json
{
  "麻婆豆腐": { "credit": "摄影：张三", "license": "已获授权" }
}
```

文件名和菜名对不上时，用 `index.json` 显式指定：

```json
{
  "麻婆豆腐": { "file": "IMG_2043.jpg", "credit": "摄影：张三" }
}
```

## 自动采集（国内通道）

如果不想手工找图，可以用 `npm run photos:cn`：博查搜索 → 抓页面主图 → 百度菜品识别核验 → 存到 `_candidates/`。

```bash
cp .env.example .env      # 填 BOCHA_API_KEY 与 BAIDU_API_KEY / BAIDU_SECRET_KEY
npm run photos:cn                    # 全部省级代表菜
npm run photos:cn 麻婆豆腐 剁椒鱼头   # 只跑指定菜
npm run photos:cn --no-verify        # 跳过核验（不建议，图容易错）
```

**核验这一步很关键**：搜索引擎给的是页面主图，经常是店铺招牌或菜单。百度「菜品识别」返回菜名 + 置信度，挡掉「图不对菜」。
`_candidates/` 里的图必须人工过一遍，选中的改名成 `菜名.jpg` 移到上一级目录，再跑 `npm run photos`。
