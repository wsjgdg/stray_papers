# 任务书：4A 景区描述补写（批 1，300 条）

> 交接对象：外部 AI / 并行 agent
> 交付物：一个 JSON 文件（只产 JSON，不要改仓库里的任何源文件）

---

## 1. 背景

「华夏探索」（Next.js 文旅应用）内置了 5936 条中国 A 级景区/POI。其中 **336 条 5A** 的简介已经全部写完（存于 `src/lib/poi-descriptions.ts` 的 `SCENIC_DESCRIPTIONS`），
但 **453 条低等级条目（3A/2A/无等级）** 目前只能显示一条机器模板句（4A 的 4320 条已交付），用户看到的是「XX 是一处 4A 级景区……」这种没有任何信息量的文字。

本批目标：为其中 **300 条**写出可直接上线的中文简介。

## 2. 输入

- 清单文件：`docs/outsource/desc-4a-batch1.json`
- 结构：
  ```json
  {
    "items": [
      {
        "name": "景山公园",
        "sourceName": "景山公园",
        "address": "北京北京市西城区……",
        "category": "城市地标"
      }
    ]
  }
  ```
- `name` 是**当前库内展示名**（可能已被清洗过），`sourceName` 是 A 级名录原始名（两者常相同；不同时说明该条被改过名）。
- `address` 可用于定位（省市县），但**不要**把地址原文抄进描述。

## 3. 硬性规则

### 3.1 长度

- **60–110 个汉字**（含标点计入，但不许靠堆标点凑数）。
- 少于 60 或超过 110 会被机器校验收拒。

### 3.2 禁写内容（一条都不许出现）

- 门票、价格、人均、性价比
- 开放时间、营业时间、闭园、售票
- 预约、限流、实名、抢票
- 电话、官网、二维码
- 「最佳季节」「建议游玩 X 小时」「几月去最好」
- 「必打卡」「不虚此行」「yyds」这类营销话术

原因：这些字段在应用里是独立的结构化字段（门票走 `quoteTicket`、开放时间走高德 `openTime`），文案里重复写会与真实数据冲突。

### 3.3 事实纪律（最重要）

- 只写**你有把握**的事实：地理位置（山/湖/峡谷/古城/寺庙/博物馆等本体属性）、形制特征、历史沿革、文化主题、代表性景观构件。
- **数字**（面积、海拔、年代、层数、长度、洞厅数量等）如不能确认，宁可不写，**不要猜**。
- 强断言（「世界遗产」「全国重点文物保护单位」「中国最大/唯一/第一」「国家级」）**必须能对上**，不确定一律降级为描述性表述。
- 寺庙类不要臆断创建朝代与开山祖师；陵墓类不要臆断墓主生平细节；博物馆类只写馆藏主题方向，不编具体文物名。
- 商业综合体/工业旅游点/文旅小镇这类「名字即说明」的条目，写它的**业态与空间形态**（如「以 X 为主题的一站式商业综合体，含……业态」），不要编历史。

### 3.4 文体

- 一段话，不分点，不用「首先/其次」。
- 第三人称客观陈述，可带一句画面感描写，但不要抒情散文。
- **不要**以「XX景区位于……」开头重复名字（名字已经在标题上）。可以直接切入特征，或用「地处……」这类省略主语的写法。
- 不要出现「本条」「该景区条目」「据资料」之类元叙述。

## 4. 输出格式

文件名：`out-desc-4a-batch1.json`。

**交付通道（二选一，项目方都会处理）**：

- 首选：把完整 JSON 贴在回复里的一个 ```json 代码块中；
- 备选：写到仓库的 `docs/outsource/out-desc-4a-batch1.json`。

除这个文件外**不要改动仓库任何其它文件**（`src/` 一个字都不要动）。项目方用
`node scripts/ingest-outsource.mjs <文件> --kind=desc --batch=1` 回收你的交付：
它会抠出 JSON、核对条数/id/name，通过后落到标准路径；任一项不符直接拒收并打印差异。

```json
{
  "task": "4A-描述补写-批1",
  "count": 300,
  "items": [{ "id": "输入里的 id", "name": "景山公园", "desc": "……" }]
}
```

要求：

- `name` **逐字符照抄**输入里的 `name`（不要顺手改成你认为正确的名字，不要补全称，不要改标点）。
- 如果输入条目带 `id`，请把它**原样回填**到输出条目里（`{"id": "...", "name": "...", "desc": "..."}`）。
  原因：库内同一条目在「名录补充条目」和「城市 POI 包」两套来源里可能同名（北京/武汉都有「中山公园」），
  `id` 是唯一能区分两者的锚点；缺了它下游合并只能靠名字猜，会把描述串到别的城市。
- 如果你认为输入名本身有错（错字/明显 OCR 错误），**照抄原名**写 desc，另外在 `nameIssues` 里单独列出：
  ```json
  "nameIssues": [ { "name": "原样", "suggest": "建议名", "reason": "依据" } ]
  ```
- `items` 条目数必须等于输入条目数（300），**不允许跳过**（少一条整批拒收）。确实查不到可靠信息的，写「通用型」描述（只写能由名字+地址推出的本体属性），并在该条加 `"confidence": "low"`。
- 描述里如果提到景区名，用简称（如「景山公园」→「景山」），不要整串重复。
- **名字自带禁写词不用绕**：有些官方名本身含「打卡」「元」（如「三元宫」「陆家嘴三件套打卡位」），
  照抄即可——机器验收会先剥掉景点名再扫禁写词，你不必为此改写正文。
- 正文里不要出现「数字+元」的写法（3 元、八十元都不行）；要提价格就整段不写。

> **合并键由项目方处理**（你不需要关心）：
> 输入里的 `mergeKey` 已经算好——值为 `城市::名` 的走城市限定键（POI 城市包条目），其余用裸名（名录 extras 条目）。
> 你只要保证 `id` / `name` 回填准确即可。

## 5. 自检（交付前必须跑）

1. 逐条数字符（含标点，按 unicode 字符数算），确认 60–110。
2. 全文搜索下列词，命中即改：`门票 票价 开放时间 营业 预约 限流 电话 最佳季节 建议游玩 打卡 必去`
   （「元」不用单独搜：只禁「数字+元」；景区名里带「元」是允许的）
3. 检查所有数字断言：每个出现的数字，问一句「我能给出处吗」，答不上就删。
4. 检查 `name` 与输入逐字符一致（可逐行 diff 输入清单）。
5. 确认没有一条描述以名字原文开头重复。
6. 确认 `items` 条数 = 300，`id` 全部回填。

> 项目方的机器验收（你本地没有这些脚本，这是给你看我们怎么查的）：
> `node scripts/check-desc-facts.mjs docs/outsource/out-desc-4a-batch1.json`
> —— 长度区间、禁写词（扫前先剥景点名）、name 是否在目标清单内、数字与强断言抽取。
> 目标清单按交付文件名自动推断为 `desc-4a-batch1.json`，不用再传 `--targets`。
> 合并器：`node scripts/merge-out-desc.mjs docs/outsource/out-desc-4a-batch1.json`（整批验收，任一硬违规整批拒收）。

## 6. 参考样例（这是**已上线**的 5A 写法，模仿其密度和语气）

- 「清代规模最大的王府，『一座恭王府，半部清代史』，花园中西洋门、大戏楼与福字碑并称三绝。」
- 「中国现存最完整的古代城垣，13.74 公里可骑行一周，永宁门瓮城与城墙马面构成完整的防御体系。」
- 「开凿于唐代的 71 米弥勒坐像，『山是一尊佛，佛是一座山』，世界文化与自然双遗产。」

注意这三条的共同点：**一个定性判断 + 两到三个具体构件/特征 + 一个能被验证的数字或称号**。

## 7. 一个容易踩的坑：景点自己的名字里就带禁写词

库里有些景点的官方名**本身**含禁写词。已确认的实例：

| id            | 景点名             | 名字里自带的禁写词 |
| ------------- | ------------------ | ------------------ |
| `poi-上海-14` | 陆家嘴三件套打卡位 | 打卡               |

如果你在描述里照抄了全名，验收脚本会把它当成你写进去的违规词，**整批拒收**。

合并器已经处理了这一层（扫描描述前先剥掉该景点的名字，只检查你新写的内容），
但保险起见仍是那句话：**描述里不要照抄全名**，用简称（这正是第 3.4 节的要求）。
名字里带「打卡 / 门票 / 温泉 / 公园 / 广场」这类常见词时尤其要注意。

## 8. 交付后

把 JSON 文件交给项目方（我）。我方会跑 `scripts/check-desc-facts.mjs` 做机器验收，
再做人工抽检（重点看：数字断言、强断言、名字是否照抄）。
未通过部分会原样退回重写。
