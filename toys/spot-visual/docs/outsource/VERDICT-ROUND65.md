## 一、逐条详述

### #1 交付目录矛盾 —— 成立，已修

- 事实：`TASK-4A-DESC.md` §4 写「放在你自己的输出目录，**不要**写进项目仓库」，而 `PROMPT-4A-DESC.md` 只给了文件名没给路径；
  `CRON-DELIVERY.md` 的监控判据是扫 `docs/outsource/` 下的 `out-*` 文件。三者对不上。
- 处理：两份任务书 §4 与两份提示词统一改成「**交付通道二选一**：① 把完整 JSON 贴在回复的一个 ```json 代码块里；② 直接写 `docs/outsource/out-<kind>-batchN.json`」，
  并写明「除这个文件外不要改动仓库任何其它文件」。

### #2 交回通道缺失 —— 成立，已修（本次最关键的落地）

- 事实：仓库里确实没有任何「把外部交回的东西收进仓库」的入口；cron 只认 `docs/outsource/out-*.json`。
- 处理：新增 `scripts/ingest-outsource.mjs`：
  ```
  node scripts/ingest-outsource.mjs <文件|-> --kind=desc|profile --batch=N
  ```
  - 从文件或 stdin 抠出 JSON（容忍 ` ```json ` 代码块、前后说明文字、顶层数组）；
  - 与输入清单逐条核对：**条数、id 集合、name 逐字符一致、payload 字段非空**，任一不符直接拒收并打印差异、**不落盘**；
  - 通过则原子写入 `docs/outsource/out-<kind>-batchN.json`，并打印下一步该跑哪个合并器。
- 实测（沙盒，不碰真仓库）：9/9 通过 —— 合法批落盘、条数不符拒收、代码块文本能抠出 JSON、name 不一致拒收、
  payload 为空拒收、顶层数组接受、描述批用 `desc` 字段通过。

### #3 city 截断 —— 成立，且比外部估计的更严重

- 事实（实测）：档案 48 批共 4753 条，`city` 字段**没有一条**等于正确地级市。典型：
  - `scenic-安庆-1296` city = `"安徽安庆市桐"`（应为「安庆」，后半截是县名被切了一半）
  - `scenic-池州-1341` city = `"安徽池州市青"`（应为「池州」）
  - 根因：旧生成器用 `address.match(/^([^市]{1,4}市[^区县]{0,6}[区县])/)` 去截地址，
    而名录地址本身是「省+市+县」三重复写（`安徽安庆市桐城市安徽安庆市天柱山景区`），正则必然切错。
  - 外部报「4073/4753」是低估：**实际 4753/4753 全错**（POI 条目的 city 是地址前缀「北京市西城区」，与 id 城市不同名）。
- 根因之二：TASK-SPOT-PROFILE §2 原文写「`address` 是**唯一权威定位依据**」，但 address 恰恰是脏串 —— 外部照它推算交通字段会系统性填错。这条判断完全正确。
- 处理（已落地）：
  - 生成器改为按「**id 里的地级市 + 地址逐级剥离**」解析，输出四个字段：
    `province`（省）、`city`（地级市，权威）、`district`（区县）、`address`（折叠重复段后的参考值）。
  - 数字 id 的手工精选条目（「1」「10」「14」…）从地址解析地级市与区县；
    名录没登记城市的极少数条目（`scenic--262` 之类）用应用自己的城市中心表反查城市名。
  - 解析结果（实测全库）：有城市 5867 条、无城市 34 条、有城市但无区县 48 条（都是确实无区县级信息的）。
    档案 48 批：4753 条里无 city 仅 **13** 条（0.27%）、无 district 48 条。
  - 新增守护测试：按 id 回库重算，逐字段比对清单里的 province/city/district，**库一改就红**，防清单漂移。
- 提示词同步改写：明确「`city` 是权威城市、交通字段只按 city+district 推算、不许凭名字猜城市」。

### #4 验收口径不同步 —— 部分成立，已修

外部的三点里，**两点成立、一点不成立**：

| 外部说法                                                     | 核实结果                                                                                                               |
| ------------------------------------------------------------ | ---------------------------------------------------------------------------------------------------------------------- |
| check-desc-facts 用「总字符数」、merge 用 code point         | ❌ **不成立**：`check-desc-facts.mjs` 原第 84 行就是 `const len = [...desc].length`（code point），与合并器同口径      |
| check-desc-facts 扫 `description` 字段                       | ✅ **成立且是真 bug**：外包产物字段叫 `desc`，脚本读 `it.description` → 整批 300 条会被判「缺少 description + 长度 0」 |
| 目标清单默认 `desc-targets-5a.json`，4A 批必须加 `--targets` | ✅ **成立**：默认值写死，对 4A 批不传 `--targets` 会把 300 条全判「不在目标清单」                                      |
| check-desc-facts 不剥名字                                    | ✅ **成立**：合并器有 `desc.split(src.name).join("")`，脚本没有                                                        |

- 处理：`check-desc-facts.mjs` 已改——① 同时接受 `desc` 与 `description`；② 扫禁写词前先剥景点名（与合并器同口径，
  这样「三元宫」「陆家嘴三件套打卡位」这类名字自带禁写词的条目不会被误判）；③ 目标清单按交付文件名自动推断
  （`out-desc-4a-batchN.json` → `desc-4a-batchN.json`），`--targets` 仍可显式覆盖。
- 实测（沙盒）7/7 通过：desc 字段、自动目标清单、名字自带禁写词不误判、description 字段兼容、
  正文里的「门票」仍拦、长度越界仍拦、name 不在清单仍拦。
- 提示词里补了确切的验收命令与参数（外部本地没有这些脚本，任务书 §5 也补了同样的说明）。

### #5 「元」字规则 —— 不成立，但按你说的做了（零成本保险）

- 「三元宫」不含阿拉伯数字，`\d+\s*元` 不匹配；实测本批 300 条含「元」的名字只有 1 条、命中数 0。
- 但「正文里出现数字+元」确实是硬违规（如「门票 30 元」会同时命中「门票」和价格数字两条规则）。
  已在提示词与任务书里写明「正文不要出现数字+元；景区名里带元不受限」——不影响任何条目，只是把口径写死。

### #6 名称漂移 —— 不成立，**建议不采纳**（并说明依据）

- `reserved-names.txt` 的定义是「**撞名黑名单** = 应用前 301 条后的库内名称」（4577 行），
  也就是**当前**库里的名字，不是改名前的旧名表。命中恰恰说明名字是当前的。
- 实证：按 id 回库逐条比对 `docs/outsource/desc-4a-batch1.json` 的 300 条 →
  **库里找不到 0 条、名字与当前展示名不一致 0 条**。
- 批 2–15 是常驻生成器从当前库现生成的（`tests/gen-desc-batches.test.ts`），名字本来就是当前展示名。
- 结论：**无需冻结名称清洗合入**。合入按 id 落键，改名不影响已交付数据；
  qc 抽检时若页面显示名与清单名不同，以 id 为准即可。

### #7 count 语义 —— 已明确写死

- 合并器是整批验收：`items.length !== input.items.length` → 打印差异、退出码 1、**不落盘**。
- 已在两份提示词 + 两份任务书里统一措辞：
  「items 必须正好 300/100 条，**绝不允许少交**；实在写不出就写通用型描述并标 `"confidence": "low"`」。

### #8（我方主动补）档案清单字段不够用

原清单只有 `city` 一列，且语义混乱。现在是 `province` / `city` / `district` / `address` 四列，
TASK §2 的示例也同步更新。
