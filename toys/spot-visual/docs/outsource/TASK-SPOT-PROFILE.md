# 任务书 F：景点档案结构化字段（长期工程）

> 交接对象：外部 AI / 并行 agent
> 交付物：每批一个 JSON 文件（只产 JSON，不要改仓库里的任何源文件）
> 规模：**4753 条，48 批 × 100 条**（5A 336 + 4A 4417），按每天 1–2 批推进，**一个月起步**

---

## 1. 背景：这个任务为什么存在

「华夏探索」目前每条景点只有：名字、一张图、等级、一段简介。
但决定「去不去、怎么去、去了待多久」的信息**全都没有**，而且它们**不能写进简介**——

描述任务（`TASK-4A-DESC.md`）里明确规定：门票、开放时间、预约、电话、建议游玩时长、最佳季节 **禁止出现在文案里**。
原因：这些是要给用户在详情页上一行行看的**结构化字段**，混在散文里既检索不了，也会和真实数据打架。

所以它们必须单独以数据形式补齐。这就是本任务。

### 补齐后页面上会多出来的东西

| 页面位置   | 新增内容                                                                                                               |
| ---------- | ---------------------------------------------------------------------------------------------------------------------- |
| 详情弹窗   | 门票（旺季/淡季 + 优惠政策）、开放时间（旺淡季）、建议游玩时长、最佳月份、交通（最近机场/高铁 + 从市区车程）、注意事项 |
| 筛选与排序 | 「可当日往返」「适老友好」「亲子友好」「免票」等筛选条件                                                               |
| 行程单     | 自动计算每站停留时长，行程总时长不再靠猜                                                                               |
| 预算沙盘   | 门票取真实票价，不再用等级估算                                                                                         |

## 2. 输入

- 清单：`docs/outsource/profile-batchN.json`
- 每条形如：
  ```json
  {
    "id": "scenic-安庆-1296",
    "name": "天柱山景区",
    "province": "安徽",
    "city": "安庆",
    "district": "桐城市",
    "level": "5A",
    "address": "安徽安庆市桐城市天柱山景区",
    "category": "自然风光"
  }
  ```
- 行政区字段（脚本从「id 城市 + 地址」解析，守护测试会按 id 回库重算比对，**与库永远一致**）：
  - `city` = **地级市**（安庆 / 池州 / 北京…），是推算交通字段的权威依据；
  - `district` = 区县（桐城市 / 延庆区…），可能为空串（该景区确实无区县级信息）；
  - `province` = 省；`address` = 地址参考，个别条目带重复的行政区前缀，忽略重复段即可。
- 交通字段（`nearestRail` / `driveFromCityMin`）只能基于 `city` + `district` 推算，
  **不许凭景区名字联想城市**。`city` 为空串的极少数条目（名录本身没登记城市）按 `address` 判断并在 `notices` 注明依据。

文件名：`out-profile-batchN.json`

```json
  "batch": 1,
  "count": 100,
  "items": [
    {
      "id": "scenic-北京-0",
      "name": "故宫博物院",
      "profile": {
        "ticketPeak": 60,
        "ticketOff": 40,
        "ticketNote": "旺季60元/淡季40元；珍宝馆10元、钟表馆10元另计",

        "openHours": "4月1日-10月31日 08:30-17:00（16:00停止入院）；11月1日-次年3月31日 08:30-16:30（15:30停止入院）；周一闭馆（法定节假日除外）",
        "suggestedHours": 4,

    }

```

### 字段规约

| 字段               | 类型             | 必填 | 说明                                                 |
| ------------------ | ---------------- | ---- | ---------------------------------------------------- |
| `ticketPeak`       | number \| null   | ✅   | 旺季成人全价（元）。**免费景区填 0，不是 null**      |
| `ticketOff`        | number \| null   | ❌   | 淡季成人全价；与旺季相同则填同值或 null 均可         |
| `ticketNote`       | string \| null   | ❌   | 票价补充说明（内含项目另收费、区间车票、索道另计等） |
| `freePolicy`       | string \| null   | ❌   | 免票/优惠政策（儿童、学生、老人、军人、医护等）      |
| `openHours`        | string \| null   | ✅   | 开放时间，含旺淡季差异与停止入园时间                 |
| `suggestedHours`   | number \| null   | ✅   | 建议游玩时长（小时），0.5–12，可带 0.5 步长          |
| `bestMonths`       | string \| null   | ❌   | 最佳月份，如 `"4-5月、9-10月"`；全年皆宜写 `"全年"`  |
| `nearestAirport`   | string \| null   | ❌   | 最近民用机场名（**只写机场名，不写距离**）           |
| `nearestRail`      | string \| null   | ❌   | 最近高铁/火车站名                                    |
| `driveFromCityMin` | number \| null   | ❌   | 从所属地级市中心驾车到景区的分钟数                   |
| `accessibility`    | string[] \| null | ❌   | 无障碍/适老/亲子设施，从下方**闭集**里挑，最多 6 个  |
| `needReservation`  | boolean          | ✅   | 是否必须预约                                         |
| `reservationNote`  | string \| null   | ❌   | 预约要求（提前几天、渠道、限流规则）                 |
| `officialSite`     | string \| null   | ❌   | 官方网址                                             |
| `tel`              | string \| null   | ❌   | 景区电话                                             |
| `notices`          | string \| null   | ❌   | 注意事项（闭馆日、禁带物品、穿着要求、高原反应等）   |

`accessibility` 闭集（**只能用这些词，不要自造**）：

```
无障碍通道 | 轮椅租借 | 母婴室 | 适老步道 | 老年人优惠 | 儿童游乐区 |
无障碍卫生间 | 观光车/电瓶车 | 索道/扶梯 | 医疗服务点 | 寄存柜 | 停车场
```

**必填项查不到怎么办**：填 `null`，并在该条标 `"confidence": "low"`。
**绝对不许编造**——尤其是票价和电话，编错比不填危害大得多。

## 4. 事实纪律

1. **票价**：必须是**成人的大门票全价**，不含内部交通（索道/观光车/船票）与园中园。
   内部项目另收费的写进 `ticketNote`。
   免费开放的写 `0` 并注明（如「免费开放，需预约」）。
2. **开放时间**：要写明**停止入园/停止售票时间**，这是用户最常踩的坑。有闭馆日的必须写。
3. **建议时长**：按「一般游客走主线」估算，不是深度玩家也不是走马观花。
   大景区（如故宫、九寨沟）按沟内/园内主线 4–8 小时；小镇/寺庙类 1–3 小时。
4. **交通**：只认真实存在的机场/车站名。找不到就 `null`——
   例如偏远景区的「最近机场」常常是 200km 外的省会机场，宁可空着也不要瞎填一个近的。
5. **预约**：2026 年大量景区实行实名预约/限流。不确定就填 `needReservation: false` 并
   在 `notices` 里写「出行前请核实最新预约政策」——**不要默认不需要预约**。
6. 数字一律用**阿拉伯数字 + 单位**（`60`、`4`、`30`），不要写「六十」「四小时」。

## 5. 自检（交付前必跑）

- [ ] `items` 条数 == 输入条数（100），一条不落
- [ ] 每条的 `id` 与输入**逐字符一致**
- [ ] 每条的 `name` 与输入**逐字符一致**
- [ ] `ticketPeak` / `ticketOff` 是非负数字或 null；免费为 0 不是 null
- [ ] `suggestedHours` 在 0.5–12 之间
- [ ] `driveFromCityMin` 在 1–600 之间
- [ ] `accessibility` 里没有闭集之外的词
- [ ] 三个必填项（`ticketPeak` / `openHours` / `suggestedHours`）若为空，该条已标 `"confidence": "low"`
- [ ] 没有任何一条是把别的景区的信息套过来的
