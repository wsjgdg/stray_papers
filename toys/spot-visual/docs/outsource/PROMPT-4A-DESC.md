# 给外部 AI 的提示词（直接整段复制）

````
你是中文文旅内容作者，现在要为一个景区数据库补写简介。

## 你要读的文件
仓库：https://github.com/wsjgdg/spot-visual （public，可直接 clone 或拉取）
- 任务规则（先读，逐条遵守）：docs/outsource/TASK-4A-DESC.md
- 本批待写清单（300 条）：docs/outsource/desc-4a-batch1.json

## 你要做的事
为 desc-4a-batch1.json 里的 300 条景区各写一段 60–110 字的中文简介。

## 三条最容易翻车的地方，务必自查
1. 长度：每条 60–110 个字符（含标点，按 unicode 字符数算，和脚本口径一致）。写完逐条数一遍，不要靠感觉。
2. 禁写：门票/价格/开放时间/预约/电话/最佳季节/建议游玩时长/打卡话术。这些在应用里是独立字段，写进文案会和真实数据打架。
3. 事实：数字（面积、海拔、年代、层数、长度）和强断言（世界遗产、全国重点文保、中国最大/唯一/第一、国家级）——不能确认就删掉或降级表述。宁可少写一个数字，也不要编一个。

## 文体
一段话，不分点。第三人称客观陈述。不要用景区全名开头重复（名字已在标题上）。不要出现「本条」「据资料」等元叙述。

## 名字不要改
- name 必须逐字符照抄输入里的 name，一个字都不能改、不能补、不能简化。
- 输入里的 city 是「地址前缀（含区县）」，只是给你定位用的，不用写进文案。
- 有些景点的官方名字本身就带「打卡」「元」等字（例如「三元宫」「陆家嘴三件套打卡位」）——照抄即可，脚本会先剥掉名字再扫禁写词，你不用为它改写正文。

## 数字与「元」
正文里不要出现「数字+元」的写法（如 3 元、八十元、门票 30 元）。要用价格概念就整段不写。景区名里带「元」不受限制。

## 输出（交付方式，二选一）
首选：把完整 JSON 贴进回复，放在一个 ```json 代码块里，前后不要有别的说明文字。
备选：如果你的环境能写文件，直接写成仓库里的 docs/outsource/out-desc-4a-batch1.json。

格式：
{
  "task": "4A-描述补写-批1",
  "count": 300,
  "items": [ { "id": "输入里的 id 原样回填", "name": "逐字符照抄输入里的 name", "desc": "……" } ]
}

### 硬性要求
- items 必须正好 300 条，一条都不许跳过。合并器按整批验收，少一条整批拒收。
- 实在写不出来的条目：写一段通用型描述（只讲地貌/文化/形制，不涉及具体数据），并在该条加 "confidence": "low"。**绝不允许少交**。
- id 必须原样回填（同名跨市靠它区分，缺了下游会串写描述）。
- 如果你发现输入名有错字，照抄原名写 desc，另在 "nameIssues": [{"name","suggest","reason"}] 里单列。

## 不要做的事
- 不要修改仓库里的任何源文件（src/ 下一个字都不要动），也不要动 docs/outsource/ 下除上面那个交付文件以外的任何东西。
- 不要写 extra 字段、不要加注释、不要在 JSON 外包裹 Markdown 代码块之外的说明文字。

## 交付前自检（不需要跑脚本，按这个清单人工过一遍）
1. 逐条数长度，确认 60–110。
2. 全文搜索下列词，命中即改：门票 票价 开放时间 营业 预约 限流 电话 最佳季节 建议游玩 打卡 必去
3. 检查所有数字断言：每个出现的数字，问一句「我能给出处吗」，答不上就删。
4. 确认 items 正好 300 条，id 与 name 与输入逐字符一致（可以逐行 diff 输入清单）。
5. 确认没有一条描述以名字原文开头重复。

然后在回复里贴：总条数、长度最小/最大值、你标记为 low confidence 的条数。
````

## 项目方（我）收到后的验收动作

0. 回收落盘：`node scripts/ingest-outsource.mjs <你贴的JSON文件> --kind=desc --batch=1`
   —— 从回复里的 JSON 抠出来，核对条数/id/name，通过后写入 `docs/outsource/out-desc-4a-batch1.json`；
   任一项不符直接拒收并打印差异，不会半写半落。
1. 机器验收：`node scripts/check-desc-facts.mjs docs/outsource/out-desc-4a-batch1.json`
   —— 长度区间（按字符数，与合并器同口径）、禁写词（扫前先剥景点名）、name 是否在目标清单内、数字与强断言抽取。
   目标清单按交付文件名自动推断为 `desc-4a-batch1.json`，无需再传 `--targets`。
2. 合入：`node scripts/merge-out-desc.mjs docs/outsource/out-desc-4a-batch1.json`
   —— 按 id 落键写入 `src/lib/scenic-desc-outsource.generated.ts`，并产出 qc 抽检文件。
3. 人工抽检：按 qc 文件里的 20 个样本 id 逐条核对事实（重点：票价口径、停止入园时间、预约默认值）。
4. 回归：`npx vitest run` + `npx tsc --noEmit`。
