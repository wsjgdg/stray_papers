What’s happening under the canvas?
This is a cellular automaton: each generation updates every cell simultaneously from its eight neighbors. In the Life rule, a dead cell is born with exactly three neighbors, and a live cell survives with two or three. New cells inherit the most common neighboring ink; ties favor the lowest-numbered tied ink, and zero-neighbor births use ink 1. Each generation takes O(width × height) time. Your starting design and rules are saved; playback history is temporary.

How does the rhythm algorithm work?
The generator spreads a chosen number of hits as evenly as possible around a 16-step cycle. Rotating shifts every hit without changing the spacing. Each step is a sixteenth note; soft and accented hits have different volumes. The four synthetic instruments are generated locally—there are no recordings or network requests.

Language guide & examples
n is the length; a[i] reads a value. Variables are created with set name = expression.
for i = 0 to n - 1
  if a[i] > 5
    write i, a[i] * 2
  end
end
return n
Use for i = start to end step -1, while condition, if / else / end, swap i, j, write i, value, mark i, and return value. For loops include their end. Arithmetic uses + - * / %; division truncates toward zero. Conditions use == != < <= > >= and and, or, not.
Try the advanced Heap sort starter: it builds a max heap, then repeatedly moves the maximum to the end. The algorithm takes O(n log n) time and O(1) extra space, excluding playback snapshots.

01 / DESIGN THE PROBLEM
What will you pack?
0/1 KNAPSACK
Choose a capacity, then make a set of items. Each item can be taken once or left behind.
YOUR ITEMSWEIGHT / VALUE
Up to 8 items. Weights are 1–20; values are 0–99. Editing the problem clears the old trace, not your items.
How does it work?
dp[i][c] is the best value using the first i items with capacity c.
For each cell, compare skipping the item with taking it plus the best value at the remaining capacity. Both choices use the previous row, so an item cannot be reused.
dp[i][c] = max(skip, value + previous[c − weight])
If an item does not fit, only skip is possible. On a tie, this version skips the item. It then traces backward to recover one optimal set.

WHY IT IS ADVANCED
The table reuses smaller solutions instead of exploring every subset. For positive n and capacity C, it takes O(n × C) time and space; this is pseudo-polynomial in the numeric capacity. Playback snapshots use additional space.

WHY IT WORKS
Dijkstra uses nonnegative costs and a min-priority queue. It guarantees a cheapest route; breadth-first search guarantees the fewest moves, but ignores the price of terrain. The search takes O((V + E) log V) time and O(V + E) space with this heap implementation, excluding stored playback snapshots.

ENCODED BITS
Bit counts compare the encoded payload with UTF-8 input bytes. They exclude the codebook/tree and byte padding, so they are not a full file-size comparison.
WHY IT WORKS
Frequent symbols get shorter prefix-free codes. This implementation treats Unicode code points as symbols, uses a priority queue, and assigns a single-symbol input the code 0. Building the tree takes O(n + k log k), plus the encoded output, for n input symbols and k distinct symbols, excluding playback snapshot work.
