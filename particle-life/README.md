# Particle Life · Node Graph Emitter

> WebGL2 GPGPU 粒子生命仿真 · 节点图行为编排 · 单文件零依赖

一个基于 **WebGL2 通用计算（GPGPU）** 的 Particle Life（粒子生命）交互式仿真器。所有粒子物理在 GPU 着色器里并行演化，所有参数通过一张"节点图"（粒子源 → 行为 → 渲染）可视化编排，无需任何第三方库，单个 `.html` 文件即可运行。

- **标题**：`Particle Life · Node Graph Emitter (WebGL2 + GPU Physics)`

- **体积**：约 2500 行 / 150 KB，单文件零依赖

- **兼容**：需支持 WebGL2 + `EXT_color_buffer_float` 的现代浏览器（Chrome / Edge / Firefox）；不满足时自动回退到 CPU 网格或 2D 兜底

- **在线 Demo**：`https://a3215c2d955320af6.app.workbuddy.host`

## 2. 核心架构与实现

### 2.1 三级后端（自动降级）

| 后端 | 触发条件 | 物理执行位置 | 适用场景 |
| --- | --- | --- | --- |
| **GPU 着色器** | WebGL2 + 浮点渲染可用 | 全并行 fragment shader（`FS_PHYS`） | 默认；3000–12000 粒子 |
| **CPU 网格** | GPU 物理初始化失败但 WebGL2 可用 | 主线程 `buildGrid` + `cpuStep`（已分级为空间网格，O(N·k)） | GPU 不可用但能跑 WebGL2 |
| **2D 兜底** | WebGL2 完全不可用 | Canvas2D 软件渲染 | 极端环境（仅保功能，封顶 4000 粒子） |

启动时按可用性自动选择，也可通过工具栏 `后端` 下拉或 `?backend=` 手动覆盖。诊断面板 `01_后端` 实时显示当前生效后端。

### 2.2 节点图数据模型（行为编排核心）

仿真不再是"一堆全局参数"，而是一张有向图：

```
particles（粒子源） → [matrix / damping / noise / mouse / repel / align / cohere] → render（渲染）
```

- **节点类型**（`BEHAVIOR_TYPES`）：`particles`、`matrix`、`damping`、`noise`、`mouse`、`repel`、`align`、`cohere`、`render`

- **可达性判定**：只有从 `particles` 出发、经连线能到达 `render` 的节点才被 `activeBehaviors()` 激活（`reachableSet()` 正向遍历）。
- **断开连线或禁用节点 = 该行为从物理中彻底移除**，且不影响其他行为。

- **手动编辑即生效**：节点面板的滑块/输入直接写 `node.params`，每帧 `collectBehaviors()` 重新汇总进物理引擎。

> 这就是为什么"矩阵面板能改但没反应"通常是 **matrix 节点未接入管线**（`hasMatrix=false` → GPU 完全忽略矩阵项），而非编辑没写入。

### 2.3 主要技术实现点

| 编号 | 特性 | 实现要点 | 默认 |
| --- | --- | --- | --- |
| **A** | 半精度物理纹理 + 异步 PBO 上传 | 状态纹理用 `RGBA16F`（`PHYS_16F`）省显存带宽；粒子属性上传走 `PIXEL_UNPACK_BUFFER` 异步 | 开 |
| **B** | GPU 内建建桶（bitonic 排序） | `?gpuGrid=1`：用计数排序 + bitonic sort 在 GPU 内建网格，免 CPU `buildGrid`。首次进入跑一次读回校验，失败自动回退 CPU | 关 |
| **D** | 吸引力矩阵 UBO | 矩阵打包进 `std140` uniform block（`vec4 u_mat[13]` = 52 浮点），索引 `[mi/4][mi%4]` | 开 |
| **G** | Web Worker 搬运 CPU 物理 | `?worker=1`：CPU 模式的 `buildGrid`+`stepOnce` 搬进 Worker 异步步进，仅服务 CPU 后端轻量场景（GPU 主场景不走此路） | 关 |
| **H** | 动态分辨率 | `renderScale` 随 EMA FPS 自适应降载（下限 0.5），仅缩放渲染、不影响物理迭代规模 | 开（×1.00） |

### 2.4 GPU 物理主循环（`gpuStep`）

每帧流程：

1. **回读坐标**（仅连线开启时）：`syncReadback()` 把 GPU 状态纹理坐标取回 CPU 端 `px/py`，供连线渲染使用（见 §4.3）。

2. **重建行为参数**：`collectBehaviors()` 汇总矩阵 / 半径 / 阻尼 / 噪声等。

3. **上传矩阵 UBO**：`bufferSubData` 写入 `matUBO`（std140 打包）。

4. **着色器演化**：`FS_PHYS` 对每个粒子并行计算邻居受力，输出新状态纹理（ping-pong FBO）。

5. **渲染**：`renderScene()` 把状态纹理绘成粒子（含拖尾 / 辉光 / 色散 / 暗角）。

CPU 路径（`cpuStep`）逻辑与 GPU 逐位等价，已用 Node 数值测试验证（见 §6）。

### 2.6 场景导出 / 导入

- **导出**（`exportScene`）：序列化节点图 + 全部参数 + 每个粒子的坐标/速度/物种，保存为 `.json`。

- **导入**（`importScene`）：按原视图宽高比 `W/w0, H/h0`
- **等比缩放**粒子坐标，并钳制 `count ≤ MAXN`（12000），再 `uploadStateToGPU()` 复位。

## 6. 验证与已知限制

### 6.1 算法级验证（已通过）

- **bitonic 排序方向**：500 例 CPU 等价逻辑全过（修正过用低位 `lo&k` 判定方向的 bug）。

- **GPU 网格 CSR 与 CPU `buildGrid` 逐格等价**：mismatch = 0。

- **Worker 演化与主线程 `cpuStep` 逐位一致**：maxAbsDiff = 0（共享初始状态后）。

- **场景导出导入 round-trip**：坐标缩放 + count 钳制正确。

- **矩阵/调色板数据完整性**：索引与 RGB 范围校验通过。

- **矩阵手动编辑链路**：`matrix_chain_verify.js` 全部 PASS。

### 6.2 已知限制 / 注意点

- **GPU 着色器、UBO、Worker、PBO 路径在沙箱内无法实跑**（`gl=null`），以上算法验证均为 Node 数值等价 + 真机确认，非沙箱 GPU 执行。

- **12000 粒子 GPU 主场景的 FPS 天花板**来自 Intel Arc 等核显的 O(N·k) 邻居算力墙（实测约 21.7 FPS）；B/D/G/H 各项收益中低，已按指令落地。

- **G（Worker）对 GPU 主场景零作用**：Worker 无 GPU 访问，仅服务 CPU 后端轻量场景，属架构补齐项。

- **连线开启时每帧同步 `readPixels`**：约 192KB 回读，连线默认关闭故不影响主路径性能。

- **自动变形（`autoMorph`）默认 false 且无 UI**：若误开启会周期性覆盖矩阵，导致"手动改了被还原"的错觉。
