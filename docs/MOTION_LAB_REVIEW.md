## 为什么选第 4→5 幕

正式反诈关的第 4 幕：模拟账户显示盈利 6,000 元；第 5 幕：提现前客服要求先交 20% 保证金。两件事适合构成**表象/条件**这一视觉矛盾。用户不是点击“下一幕”等待预设视频，而是亲手把显示盈利的表面向左拉开；拉出的缝里出现不可忽略的提现条件。文字均为教学综合示意，非真实账户/交易。

## 一次操作对应的镜头与状态

1. **0% / 表象**：冷青的“账面”表面，细密数字刻度与向上走势；HTML 清晰排出“+6,000”，但下方提醒这只是屏幕数字。
2. **拖动中 / 裂口**：用户抓住右侧六边形裂口向左拉。`PointerEvent` 的位移更新目标进度、移动速度改变局部折射扰动；程序片元着色器生成有细微噪声的不规则热缝、金色亮边，前后两种材质在缝边交界。HTML 文案使用同一个进度同步裁切，风险文字从缝中被揭示，而不是独立淡入。
3. **松手 / 余势**：未过阈值回弹，越过阈值或快速向左掷出则继续揭开；阻尼弹簧使松手后仍有余势。可用滑杆在任意位置前后比较，也可一键“直接看真相”/“合上再试”。
4. **100% / 真相**：红色安全纸纹理与“提现？先交钱。20%”成为主视觉；结果区写出真实行动：停止转账、保留证据、独立核验。**不把错误转账包装为奖励**。

## 实际使用的技术（区别于前一轮原型）

- WebGL 1 原生 shader：程序化账面走势、细网格、安全纸斜线、噪声、随指针速度变化的裂口扰动和边缘发光；不用图片、模型、云端、第三方库或版权素材。WebGL 获取/编译失败则回退 CSS 底图，DOM 文案和操作仍正常。
- 一个 `p∈[0,1]` 同时控制 GPU 裂口、DOM 文案裁切、把手位置、滑杆数值、结果标签；不是先让一处动完再播放另一处动画。文本始终为可读的 HTML。
- `requestAnimationFrame` 的简化弹簧/阻尼；触屏与鼠标共用 Pointer Events。输入速率在移动时映射为 shader 局部扰动；停止后脉冲衰减。场景离开可视区或切到后台即停止 WebGL 循环；手机限制渲染像素比到 1.2，桌面到 1.6。
- 减少动效偏好使目标状态**即时完成**，不留半透明中间态；原生范围滑杆可键盘操作；无 JS 时有明确“先交保证金”结论和完整第五关链接；代码不写入进度或采集数据。

## 已检验 / 尚未证明

- Chromium `file://` 320、375、768、1280、1440px：WebGL 着色器编译成功，页面无横向溢出；已目视检查桌面和手机 0%、55%、100% 三态。沙箱截图临时注入中文字体，不等同真实用户设备验收。
- 桌面指针拖动到阈值后揭开，短拖会回弹；减少动效下按钮可瞬时揭开/重置，原生滑杆的方向键可改变状态；Chromium 触摸事件测试能从手机宽度拖到真相；无 JS 提要可见；模拟 WebGL context lost 时仍能通过滑杆看到完整结果。
- `smoke.js` 校验本地页面引用与 motion-lab.js 语法；旧六关 `test.js` 回归通过。
- **没有**真实手机 GPU 的帧时间/发热/触控手感数据；不宣称达到某个 FPS。着色器是为了验证材质与交互因果，尚无资产质量或审美获得用户认可的证据。正式部署前需目标手机设备复核及性能采样。
