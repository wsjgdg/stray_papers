# 「AI 探索基地」六关前端重做计划

> 2026-11-05｜状态：**首轮六关改版已落地，待用户视觉评审与目标设备复核**。以下保留设计决策与验收标准；本轮实现及浏览器验证见文末记录。

## 一、问题判断与改版边界

现状的主要问题不是「动效不够多」，而是**六页几乎都由同一套白底圆角卡片、左侧色条标题、等宽栅格和相同的滚动淡入组成**：信息主次不明显，关键体验（成果、图表、实验、骗局、练习）没有成为舞台中心。全站正文容器可达 1240px，长段落也会被拉得过宽；页面内联样式多、动效入口分散，局部交互又依赖逐字等待和 3D 翻卡。只给现有卡片加更多动画，会让阅读更累。

**必须保持：**六关名称与顺序、现有核心观点和事实/来源、①的五类成果与提示词、②的时间线/数据/行业、③的可玩的本地实验室与三个项目、④的三层副业路线和风险提示、⑤的七幕剧本及双分支/心理机制/话术词典/核实工具、⑥的提示词三要素/三档预置回答/Agent 流程/L1–L5；打卡、结业证书、离线打开、不依赖在线 API。允许重排呈现顺序、拆分长文、精简重复引导语，但不删关键内容、不伪造「真实 AI 生成成果」。

**范围：**重点重做六关及全站共享导航/组件；首页和结业页同步套用新视觉语言与导航，避免前后风格割裂，但不改变它们的核心内容。继续保持纯 HTML/CSS/JS、本地 GSAP/Chart.js/confetti，不引入框架或 CDN。原有未提交的修复（见 `docs/REVIEW.md`）作为改版基线，不覆盖或回退。

## 二、设计方向：一本可亲手操作的「AI 探索手册」

不要科技蓝光、玻璃拟态或满屏发光卡片。用**杂志式编辑排版 + 实验手册的标记与刻度**：暖纸色作阅读底，深墨色作正文，朱红/铜色作行动强调；用章号、细分隔线、侧边注释和大数字形成节奏。反诈页可转为更克制的警示红，不把骗局做成刺激的投资游戏。

| 层级 | 规划 |
|---|---|
| 字体 | 系统中文无衬线为正文，系统宋体仅作章节题/重点引句；不依赖联网字体。移动端正文保持约 18px、行高 1.65–1.8；标题使用 `clamp()`，避免手机上大字溢出。 |
| 宽度 | 外层 12 列栅格、桌面最大宽约 1280px；**长文阅读列单独限制在约 680–760px**；图表/实验/成果舞台可跨 8–12 列。移动端改单列，保留约 16–20px 两侧边距。 |
| 配色 | 全站固定阅读背景/墨色/行动色；每关用一个低饱和辅助色标识章节，色彩只服务导览与数据，不靠颜色单独传递风险/完成状态。文字对比至少 WCAG AA。 |
| 组件 | 做「章首页眉 / 证据条 / 大数字 / 对话舞台 / 分层路线 / 来源注记 / 上下关导航」几类有职责的组件，减少无差别 `.card`；大留白给重点，不把所有信息都装进盒子。 |
| 导航 | 紧凑顶部栏显示站点名、当前章、6 段进度、打卡状态；章末固定「上一关 / 下一关」。小屏按钮不挤压标题，保证触控目标至少 44×44px。 |

### 页面模板（不是六张相同模板）

每关沿用「章号与一句核心主张 → 主舞台 → 证据/练习 → 一句话带走 → 下一关」，但**主舞台各不相同**。章节标题和导览统一，主内容允许完全不同的构图。首屏直接展示本关最有说服力的一件事，不让一大段导语压在体验之前。

## 三、六关逐页排版与动效

| 关卡 | 新排版 / 主体验 | 有意义的动效（只在首次进入视野或用户操作时触发） |
|---|---|---|
| **① AI 能做什么** | 改成「成果展台」：首屏突出一件成果，旁边直接标出它解决的事；其余四个案例交替使用“成果 / 怎么做 / 可照抄提示词”双栏。五类案例全保留；提示词改为清晰的展开区/按钮，不再把整块内容藏在 3D 翻面后。演示回答明确标注为预置示意。 | 成果区域轻推入，提示词展开 200–250ms；可选文字演示应有「立即显示全文」，正文不能依赖打字完成才能阅读。 |
| **② AI 趋势与行业** | 「可读时间轴 + 数据编辑页」：桌面 8 列时间线、4 列关键数字摘要；增长图表独占一行，下面五个行业做紧凑对照矩阵，来源紧贴数据。手机时间轴改竖向，图表仍能读标签和数值。 | 时间轴刻度随滚动逐项点亮；计数和柱图只运行一次，时长约 0.8–1.2s，**最终值始终以文本可读**；减少动效时直接显示终值。 |
| **③ 儿子的 AI 实验室** | 「实验台」：把本地 iframe 当主角，先给 2–3 步玩法指引，再给足够大的可操作视口；另设“单独打开实验”链接。三个项目做带项目名、用途、AI 参与说明和真实仓库链接的项目档案，不用三张等高白卡。 | 实验说明按步骤出现；iframe 本身不随滚动位移、不遮挡鼠标/触控，也不因为动画延迟加载操作。 |
| **④ 副业地图** | 「三层路线图」：零门槛 / 进阶 / 深度依次形成垂直路径；每层有学习周期、第一步、所需工具、合规/风险提示。进阶层三个方向横向对照，避免套娃卡片；收入预期与防骗红线保持可见。 | 只做路线节点的短距离连线/高亮，不用会暗示“收益上涨”的夸张曲线或金币庆祝。切换方向时内容即时可达。 |
| **⑤ 骗局解剖室** | 「模拟对话 + 同步解剖」：桌面主对话 7–8 列、右侧当前幕解析 4–5 列；手机按“对话 → 解剖 → 选择”阅读顺序排列。7 幕、第四幕双选择、两条分支、风险话术词典、核实工具与事实层全部保留；关键警示用高对比警示条，不靠红色恐吓。 | 每幕只对**新消息**做 150–250ms 进入；禁止长时间强制逐字等待，提供「跳过/显示全文」；分支点给明确反馈，不用庆祝投资行为。能随时重走，且不因动画使按钮消失。 |
| **⑥ 提示词学院** | 「练习工作台」：角色/背景/要求三项先做可对照的配方卡，三档预置提示词放在可选列表，选择后在旁边展示相应预写回答和点评；Agent 四步用清晰流程图；L1–L5 用行动清单收尾。手机题目与回答上下排列。 | 选项反馈 150–200ms、当前选中态明显；快速切换不能被旧答案异步覆盖。Agent 流程只做一次逐步强调，减少动效时直接显示全部。 |

## 四、动效规范（先有阅读，再有动画）

- 统一时长：页面首屏 400–600ms；普通内容 350–500ms；按钮/展开 150–250ms；连续元素错峰约 60–100ms，整组最多约 800ms。只动画 `opacity`/`transform`，避免布局抖动。
- 只在**内容已经插入 DOM 后**注册滚动触发；触发一次即完成，不做大面积滚动绑定、视差、滚动锁定或无意义的统一淡入。新内容默认可读，JS/GSAP 失败不能留下一大片透明内容。
- 不把「减少动态效果」理解成降低速度：`prefers-reduced-motion: reduce` 时直接给最终状态，停掉打字机、位移、图表动画和庆祝粒子；普通模式的庆祝也只在真正完成时触发一次。
- 互动优先于表演：先让用户看见和操作，再决定是否播放微动效；长对话可一键显示全文，不用等十几秒才能继续。

## 五、实施顺序与交付检查点

1. **基线与视觉定稿**：记录六页内容/外链/交互清单，保留现有功能断言；做桌面和 375px 的简易线框/样式样板（章首页眉、成果模块、按钮、导航）。先重做①为完整样板并让用户确认视觉方向，**确认后**再批量改六关，避免一次做完又推倒。
2. **共享系统**：新设计令牌、排版栅格、章节头/导航、阅读列、组件状态、减少动效策略；把散落在 HTML 内的重复视觉规则迁入 CSS，保持脚本模块的内容逻辑不变。
3. **逐关实现**：①成果 → ②趋势 → ③实验室 → ④副业 → ⑤反诈 → ⑥学院。每关完成就跑静态检查与该关交互回归，不等六关做完才一起发现问题；⑤单独做双分支验收。
4. **首尾统一**：首页六关入口和结业页应用同一导航/字体/章节语言；不改进度 ID、链接路径、解锁条件与事实来源。
5. **浏览器验收与交付**：320/375/768/1280/1440px、200% 文字缩放、键盘、触屏、减少动效、断网；逐关截图对照、无横向溢出/内容遮挡/空白隐藏、图表与 iframe 可用。完成 0→6/6、反诈双路线、学院快速切换、结业解锁；`node scripts/test.js`、`node scripts/smoke.js`、`bash scripts/build-zip.sh`。**另外必须在目标 Edge/Chrome 上双击 `file://` 实测跨页打卡与关闭重开**（此前 HTTP 测试不能替代）；若失败，先解决交付形态/进度持久化，再称离线版可用。

### 完成标准

- 六关的内容、来源、核心交互与顺序不丢；每关首屏能在 10 秒内看出“这关要体验什么”，并有明确下一步。
- 桌面端呈现有主次的 12 列构图，正文不过宽；手机端无需横向滚动，触控目标 ≥44px，正文可读；无障碍、无 JS 和减少动效模式下重要内容仍可见。
- 动效帮助理解故事/数据/选择，而不是为动而动；低性能手机操作不被动画阻塞。
- 六关全部跑通、打卡与证书正确、离线本地资源可用；若 `file://` 存储不可靠，在交付说明中明确并提供已验证的方案，不能默默降级。

## 七、视觉方向第二轮修订

用户反馈首轮虽然重排了内容，但首屏重复的「深色底 + 巨大数字」仍缺乏美感。第二轮已经改成六张原创的、与各关内容对应的概念摄影/静物画面，首页地图也呈现六张缩略图；移动端图文上下分区，不把中文覆盖在复杂照片上。详细参考和素材说明见 `docs/VISUAL_REFERENCES.md`。这是对首轮设计语言的修正，而不是更换六关的内容与玩法。
