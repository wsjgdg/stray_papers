## 项目是怎样工作的

- `ai-exploration-base/` 是纯静态、多页面中文教学站，目标是把整目录解压后双击 `index.html` 离线使用；无构建步骤、无运行时 CDN。
- 六关顺序：AI 能做什么 → 趋势 → 实验室（内嵌独立 HTML）→ 副业 → 反诈模拟 → 提示词学院；`graduation.html` 根据进度展示结业证书。
- `assets/js/progress.js` 管理 6 个任务的浏览器本地存储；`site.js` 注入导航、打卡按钮与动画；反诈剧本在 `scam-script.js`，页面交互在各 HTML 的内联脚本。
- `scripts/smoke.js` 静态检查本地引用与 JS 语法，`scripts/test.js` 检查关键交互逻辑，`scripts/build-zip.sh` 打包并解压复检。

## 本轮已修复

2. **反诈页动态生成的 14 张卡不可见**：它们在滚动动画注册后才插入 DOM，仍保留 `.reveal` 隐藏样式；已在生成后注册。
3. **反诈「停！先查一查」分支**：原先直接跳到剧终，还会把正向反馈卡覆盖掉；现在仍安全地停下投资，但继续展示第 5～7 幕并保留反馈。
4. **站内自动打卡后的按钮**：反诈模拟结束时进度徽章更新了，按钮仍显示「完成打卡」；现在按钮订阅进度变化。
5. **结业证书动效依赖缺失**：页面调用 GSAP / ScrollTrigger 但未引入；已补齐本地脚本。
6. **交互和无障碍**：翻转卡不再仅因键盘聚焦就自动翻面，加入 `aria-pressed`；学院快速切换答案时，旧异步回答不再覆盖新反馈；系统减少动效时禁用滚动 GSAP 和图表动画。
7. **进度容错和检查盲区**：忽略损坏存储中的未知 ID / 重复项；静态检查现在也覆盖外部脚本标签的本地 `src` 和内联 JS 语法。反诈数据文案区分「拨打」与「拦截」，不再承诺学完绝不会被骗。

## 下一步建议（按优先级）

- **P0｜验收双击离线进度**：`file://` 的 `localStorage` 来源/权限没有跨浏览器一致保证。原记录的真浏览器测试使用了本地 HTTP 服务，不能证明从解压目录双击打开后，跨文件页面及重启浏览器依然能保留 6 关进度。请在目标 Edge/Chrome 设备按 `index → 第 1 关打卡 → 返回 index → 关闭重开` 实测。若失败，优先选择部署为同源网站，或将六关合并到单个 HTML；不要把单页内存回退误认为跨页持久化。
- **P1｜真实浏览器端到端回归**：在 375px 与桌面宽度走通两条反诈分支、全部六关、证书解锁和 `prefers-reduced-motion`，补自动化浏览器测试（当前仓库只有 Node/jsdom 级别检查）。特别核实证书 `.reveal` 与 GSAP 两组动画在初始 `display:none` 解锁后的表现。
- **P1｜更清楚的无障碍状态**：翻转卡背面内容可被屏幕阅读器同时读取，应进一步给两面设置按状态切换的可访问性；模拟器对话和打卡结果可考虑 `aria-live`，同时避免频繁逐字朗读。
- **P2｜内容与来源审校**：核对保险/理财建议、统计口径和外链持续有效性；演示中的「AI 回答」是预写示例，应继续明确其为示意、非实际在线调用。
- **P2｜交付维护**：统一交付版本号与压缩包命名，避免文档里的静态文件数/体积随代码变更而过期。
