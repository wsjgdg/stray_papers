# 《撕开账面》改造方案｜以旧版为基准，先不动代码

> 方案版本：2026-11-05。基准是 `prototype/index.html` 的拨盘入口 + `prototype/motion-lab.html` 的「撕开账面」，**不是**后续的 `material-study.html`。本文件只提出方向，不替换页面、正式六关或离线包。

## 先把问题说准

旧版值得保留的是：**青色账面 +6,000 与红色“提现先交 20%”之间的冲突；抓住裂口向左揭开、松手回弹、可反复对照**。拨盘是进入关卡的前置体验，不应该为了改这一幕被拆掉。

旧版的问题也很具体：页面分成一大段暗色介绍、一块米白色演示区、一段暗色结语，像三个互不相干的版式；舞台被装进规整矩形。画面靠整屏渐变与片元着色器的斜缝，**没有一张真的在手下改变形态的账页**；速度仅让缝边轻微抖动。首屏提前说出 20%，减弱亲手揭开的发现感；演示下面的说明和结语重复，手机上标题/长文/舞台之间的节奏更松散。功能测试通过不代表美术过关。

## 视觉主张：一张被账面数字覆盖的“交易凭条”

不是另做一套教学控制台，也不是把纸张试验整页搬回来。保留旧版青→赤的戏剧冲突和“从右向左撕”的动作，但把**斜缝所在的表面**变为唯一主角：一张悬在深色台面上的模拟交易凭条。正面印着 +6,000、微缩安全线、编号与“尚未提现”的细字；被拉起时能看见折线、背印、边缘和投影；它下方的暗红凭证上才写“提现前先交 20% 保证金”。所有账号数字都标明教学模拟，不画真实平台标识。

配色收束为深石墨、冷青墨、旧纸色与一处风险赤铜。风险色只留给**撕开的边缘、20% 与停止转账的行动**，不把全页变成红蓝渐变。字形采用本地可离线加载的中文字体；微缩英文字只承担档案标记，不和中文主文争焦点。不要粒子雨、循环辉光、玻璃卡片、假 3D 仪表盘。

## 页面编排（不是三个上下堆叠的板块）

**桌面 ≥ 1024px**：一个近满视口的连续场景。导航是细线；左侧约 30% 留一条编辑式标题与一句问题：“账面 +6,000，能取出来吗？”；交易凭条跨中、右两侧，右缘把手明确可抓。下沿只有操作刻度、重置和跳过动画的入口。用户揭开时，红色条件从凭条后方被真实遮挡关系释放，左侧标题同步转成一句判断。随后只接一段窄版心的“现在怎么做”，不再设巨型口号和第三块结语。

**手机 320–430px**：上方问题两行以内；大数字和把手在首屏就可看到，触控区至少 44px。凭条保持可抓的面积，文字不盖住抓手和 20%；风险条件在揭开后稳定可读。操作刻度与结论在场景下沿自然接续，以下短段落只给一条原则、一组行动和来源链接。不会用 `white-space: nowrap` 硬撑中文标题，也不靠横向溢出隐藏排版问题。

下方正文以 16–18px 正文、约 650–720px 阅读宽度为基准；标题控制在 40–56px、按语义分行，不再做“和”独占一行的超大引语。场景到正文之间用同一条凭条底边过渡，而不是切成新的模板色块。

## 一次动作如何驱动整个镜头

| 状态 | 视觉与内容变化 | 用户可控之处 |
|---|---|---|
| 未揭开 | 凭条完整、+6,000 可读；20% 不抢先露出。轻微的材质呼吸只在首次进入时播放一次。 | 抓把手，或用滑杆/键盘。 |
| 慢拉 15%–60% | 手指位置决定折线高低；表面法线、背面印刷、边缘受光、下层投影同步变化。缝下的文字按真实遮挡逐段可见。 | 慢拉、快拉、从高/低位置拉，得到不同折线；不是仅改变一个遮罩宽度。 |
| 松手 | 未过阈值合回；过阈值继续揭开。释放速度继承到纸边的短暂余势，不能突然切到另一段预设动画。 | 可重复、可反向、可停在任意进度。 |
| 完整揭开 | +6,000 的表象退到次要位置，20% 与“先付钱才能提现”成为阅读焦点；不播放烟花或奖励音。 | 可查看解释、重新合上。 |

**第二个有因果的动作（控制在一小处）**：完整揭开后，给出“继续补交 / 停下核验”的明确选择。选择前者时，所谓盈利不会变成现金，只显出“又出现一笔收费”的连续要求与风险解释；选择后者时，收费链被截断，显示“不付款、保存记录、走独立渠道核验”。这是教学模拟，不发生支付，也不把错误选择做成奖励。两种结果都能撤回、重选。它不另起一个扫描器、滚筒或印章游戏；运动只服务于**账面承诺与真实行动的因果**。

## 实现边界与质量门槛

- 保留旧版 `prototype/motion-lab.html` 作对照，不直接覆盖；批准后做 `prototype/motion-lab-v2.html` 单幕垂直切片。拨盘 `prototype/index.html` 与七幕原型保持原样，只有批准后才考虑加新入口。
- 复用旧版的 `PointerEvent`、范围输入、弹簧状态和 WebGL 降级思路，但不沿用全屏渐变分屏的画法；用**细分网格 + 本地生成/绘制的账页纹理 + 双面着色/近似厚度 + 跟随变形的软影**承载纸面。一个进度/速度/抓取点状态同时驱动 GPU、DOM 文字、把手与结果，不堆互相失步的 GSAP 时间轴。受 Noho “抓取无跳变→松手承接速度”、Why Zero“动作打开叙事门”、Lando “移动端 DOM 与 WebGL 同步”的研究原则启发；不复制其资产或自称达到其质量。出处与限制见 `docs/AWARD_WINNING_MOTION_RESEARCH.md`。
- 先验收**三张关键帧 + 一个可拖动切片**：桌面/手机各看 0%、50%、100%；同屏对照旧版。只有看得出实体、背面、边缘和正确的风险揭示，才继续做第二个决定动作。若仍像渐变裂口，停下改美术，不加后处理掩盖。
- 然后测桌面/真实手机拖动与回弹、键盘与范围输入、减少动效直接可读、无 JS 静态结论、WebGL 失效后备、`file://` 离线；记录中低端设备帧时间和发热，不仅写“无溢出”。正式六关内容、顺序、来源、打卡和旧 ZIP 均不受试验影响。

**请先确认方向**：保留旧版的青赤裂口叙事，把它升级成一张会被撕起的模拟交易凭条；首屏融成一个镜头，下方只留简短核验与一个有分支的行动选择。若你更想保留旧版的“纯能量裂缝”而不出现任何实体凭条，应在制作前改定美术主体，而不是做完后再猜。
